= Contributing to standards

This repository is the canon for the hyperpolymath estate: the RSR repository
rules, the deed, k9, KYAML and I-JSON format specifications, the ADRs and owner
rulings, and the reusable CI gates that enforce them.

== Set up

[source,sh]
----
git clone https://github.com/metadatastician/standards.git
cd standards
guix shell          # the toolchain declared in guix.scm
just hooks-install  # the pre-commit guard, see below
----

`just hooks-install` installs `hooks/pre-commit`, which checks staged files
before a commit leaves your machine. It blocks banned languages and Makefiles,
warns about source files without an SPDX header, and blocks any reintroduction
of the deprecated names in `0-canon/CANONICAL-NAMES.adoc`.

== Check your change

[source,sh]
----
just validate   # structural gates: language guides, canonical names
just test       # the shell test suite
----

`just --list` shows every recipe. A change to a gate, a workflow or a format
specification usually has its own test under `scripts/tests/` or `tests/`; run
that one too, and add one when you change behaviour.

== Where things live

The tree is organised in numbered districts. `standards-map.toml` is the
authoritative map: every entry names its district, kind, lifecycle and the
gate that checks it, and `scripts/check-standards-map.sh` keeps it honest.

[cols="1,3",options="header"]
|===
|Path |What it holds

|`0-canon/` |The constitution, canonical names and the RSR criteria.
|`1-formats/` |Format specifications and their tools: deed, k9, KYAML, I-JSON.
|`2-protocols/` |Protocols, such as k9 agent coordination.
|`3-practice/` |Estate policy: languages, licences, proofs, security, this guide.
|`4-readiness/` |Readiness grades and their templates.
|`9-archive/` |Frozen history. Do not edit it.
|`docs/` |ADRs, rulings, audits, plans and reports.
|`scripts/`, `tools/`, `tests/` |The gates, their tooling and their tests.
|`.github/workflows/` |CI, including the reusable workflows other repositories call.
|===

== Report a bug, propose an idea

Issues are filed through the forms in `.github/ISSUE_TEMPLATE/`, and blank
issues are disabled (`docs/ISSUE-INTAKE-SPEC.adoc`, Rule 4):

* *Bug*: a defect, with the command, its output and the expected result.
  https://github.com/metadatastician/standards/issues/new?template=bug.yml[Open a bug].
* *Decision*: a question that needs an owner ruling, with the options and a
  recommendation.
* *Campaign*: a multi-repository or multi-step effort, with its step list.

An idea or suggestion that is none of these belongs in the repository's
Discussions, in the Ideas category, not in an issue.

Security problems are never filed in public. Follow `SECURITY.md`.

== Branches

[source,text]
----
docs/short-description        documentation
test/what-added               test additions
feat/short-description        new features
fix/issue-number-description  bug fixes
refactor/what-changed         behaviour-preserving changes
security/what-fixed           security fixes
----

== Commit messages

Commits follow https://www.conventionalcommits.org/[Conventional Commits]:

[source,text]
----
<type>(<optional scope>): <description>

<optional body: what changed and why>

<optional footer, such as Refs #123>
----

Common types: `feat`, `fix`, `docs`, `test`, `refactor`, `ci`, `chore`.
Sign your commits.

== Pull requests

* One change per pull request, small enough to review in one sitting.
* Every pull request gets CI, review bots and one generated fork-governance
  comment with the DEED, K9-DEED and Hypatia lanes. Never hand-edit that
  comment.
* Answer every review thread, either with a fix or with the reason for not
  making one.
* A pull request is ready to merge when CI is green, no thread waits on you
  and there is no merge conflict. Maintainers merge.

== Licences

Code, configuration and scripts are MPL-2.0. Prose documentation is
CC-BY-SA-4.0 (`3-practice/LICENCE-POLICY.adoc`). A new file carries the
matching SPDX header from its first commit. Never change the licence or SPDX
header of an existing file: licence changes are the owner's alone.

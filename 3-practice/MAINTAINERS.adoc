= Maintainers
:toc: preamble

This document records who maintains this repository. It summarises
link:../0-canon/GOVERNANCE.adoc[Governance], which derives its authority from
the link:../0-canon/constitution/README.adoc[constitutional district]. Where
this document and either of those differ, they win.

The estate is single-owner. There are no separate maintainers
(link:../0-canon/GOVERNANCE.adoc[Governance], Roles). The owner reviews and
merges pull requests, triages issues, rules on `status:needs-ruling` matters,
and decides licence, scope and canon changes.

== Delegation

The owner may delegate scoped, revocable permissions. A delegation is recorded
in the repository rulesets and branch protection, not in this document, so
this table does not grow when one is made.

== Agents and automation

Agents and bots act under the owner's authority, within the
link:../0-canon/constitution/CONTRIBUTION-CONSTITUTION.adoc[Contribution Constitution].
They are not maintainers, and nothing they do creates maintainer authority.

== Contribution authority

Who may land a change is set by the three perimeters of the
link:../0-canon/constitution/CONTRIBUTION-CONSTITUTION.adoc[Contribution Constitution].
Movement between perimeters uses published criteria and can be challenged.
link:CONTRIBUTING.adoc[The contributing guide] says how the perimeters apply
to this repository.

== Decisions

Decisions follow link:../0-canon/GOVERNANCE.adoc[Governance], Decision making.
There is no consensus procedure among maintainers, because there is one
maintainer of record.

== Contact

For a question about governance, open a decision issue. For conduct, see
link:CODE_OF_CONDUCT.adoc[the code of conduct]. Security problems are never
filed in public: see `SECURITY.md`.

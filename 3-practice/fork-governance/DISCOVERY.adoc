= Fork governance — how anyone finds this
:toc: left
:toclevels: 3
:revdate: 2026-10-24

A standard nobody can find is a standard nobody follows. This document lists
every surface through which a reader arrives at fork governance, and what is
enforced so that the surface cannot quietly disappear.

== The discovery chain

[cols="1,2,3",options="header"]
|===
| Reader | Arrives via | What they must find
| A human, first visit
| `README.adoc` (the front door) → routing table
| a row named *Fork governance*, linking `3-practice/fork-governance/`
| An AI agent, first visit
| `AGENTS.adoc`, then `0-AI-MANIFEST.deed`
| the same pointer, in the first screen of instructions, before any rule about how to edit the repository
| Claude / an agent with a project file
| `.claude/CLAUDE.md`
| a line that names the directory and the comment marker
| A bot doing a PR review
| the PR comment itself
| the verdict, without reading the repository at all
| A bot that scans the tree
| `.machine_readable/` directive channel
| a directive that names the lane workflows
| Any repository in the estate
| `FORK-GOVERNANCE.adoc` at its root, propagated
| the pointer, so the reader does not have to know `standards` exists
| Anyone browsing the map
| `standards-map.toml`
| the district entry, with `canonical = true`
|===

== What is enforced, and how

*The PR comment is the one surface that cannot rot.* It is generated from the
repository's own workflows on every pull request. If the system is broken, the
comment is missing or orange — visibly — rather than absent and presumed fine.

*The pointer files are propagated.* `.github/workflows/propagate-hooks.yml`
writes `FORK-GOVERNANCE.adoc` into every repository it already propagates git
hooks into, on the same pass and in the same commit. A repository that has no
copy of the file is a repository the propagation step could not reach, which is
a separate, visible failure rather than a silent gap.

*The map is checked.* `scripts/check-standards-map.sh` fails when a top-level
path has no entry, and when an entry names a path that does not exist. The
`3-practice/fork-governance/` entry therefore cannot be deleted by accident, and
cannot point at a directory that was renamed.

== The propagated pointer

`FORK-GOVERNANCE.adoc` is deliberately small and deliberately not the standard.
It says what the comment is, where the normative documentation lives, and how
to subscribe a repository. It carries its own `generated` banner and is
overwritten on every propagation pass: a stale copy in one repository is worse
than no copy, because it will be read as current.

The canonical text is
link:../../.github/fork-governance-pointer.adoc[`.github/fork-governance-pointer.adoc`]
in this repository. From there it is copied verbatim; the propagation step does
not template it, so there is exactly one version of the text.

== Why not a badge

Badges are decorative in practice: readers stop seeing them, they render as a
broken image when the branch is deleted, and they carry no evidence. The
comment carries a run link and the grids. The badge endpoint exists
(`badge.json`) for repositories that want one on a README, but it is the
secondary surface, never the primary one.

== What to do if you are reading this from a repository that is not `standards`

Everything normative lives here, in this directory. The repository you are in
calls three lane workflows and one posting workflow, all pinned to a commit of
`metadatastician/standards`. If the pins are stale, that repository's verdicts
are computed by an old renderer — check `canon-ref` against the `uses:` refs
before believing a comment that disagrees with another repository's.

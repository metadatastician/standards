== Overview

This repository serves as the canonical source for policies, templates, and specifications governing all Hyperpolymath projects. It provides:

* **Language Policy** -- Which languages and tools are permitted across the ecosystem
* **Language-Maturation Grades** -- link:4-readiness/adoption-readiness-grades/[ARG (Adoption Readiness)] + link:4-readiness/foundations-readiness-grades/[FRG (Foundations Readiness)] per-language profile templates; aggregated into the link:https://github.com/hyperpolymath/nextgen-languages[nextgen-languages] dashboard. link:4-readiness/toolchain-readiness-grades/[TRG (Toolchain Readiness)] + link:4-readiness/component-readiness-grades/[CRG (Component Readiness)] profile templates live under each framework's `templates/` directory. These letter grades are not proof grades: see **Proof Witness Grades** below.
* **Proof and Verification Policy** -- link:3-practice/PROOF-POLICY.adoc[which prover carries which obligation] (Creusot with Pearlite contracts and Verus by default for Rust; SPARK, Idris2, Agda rechecked in Rocq and Lean), and link:3-practice/PROOF-POLICY.adoc#proof-witness-grades[**Proof Witness Grades** (§8)]: `PWG-3`, `PWG-2i`, `PWG-2ii`, `PWG-1`, where lower is stronger. These say how many independent machine-checked witnesses a theory theorem has. Always write the `PWG-` prefix.
* **Machine-readable metadata** -- repo facts as clauses of `<repo>_chora.deed` (grammar link:1-formats/deed/spec/abnf/deed.abnf[`deed.abnf`]), contracts as `*.k9.ncl`, agent coordination as `coordination.k9` (see <<Machine-Readable Metadata>>)
* **Build System** -- Mustfile/justfile (no Makefiles)
* **Stable Release Gate** -- link:3-practice/release-pre-flight/V1-GATE.adoc[hard `v1.0.0` audit requirements] for all repos and multi-repo systems
* **Publication Pre-Flight** -- link:3-practice/publication-pre-flight/PREFLIGHT.adoc[submission gate] plus link:3-practice/publication-pre-flight/HOL-SUITABILITY-CHECKLIST.adoc[HOL] and link:3-practice/publication-pre-flight/ZENODO-DEPOSIT-CHECKLIST.adoc[Zenodo] checklists
* **Session Management Standards** -- link:3-practice/session-management-standards/README.adoc[canonical continuity, verify, and handover protocols]
* **Contractiles / K9** -- link:1-formats/contractiles/CANONICAL-TEMPLATES.adoc[canonical Must/Trust/Dust/Intent semantics] and Kennel/Yard/Hunt guidance
* **Governance Templates** -- Reusable CODE_OF_CONDUCT, CONTRIBUTING, and SECURITY documents
* **CODEOWNERS Policy** -- link:3-practice/CODEOWNERS-POLICY.adoc[canonical `CODEOWNERS` rules] (no catch-all/workflow lines on solo-owned repos)
* **Licensing** -- MPL-2.0 (see link:LICENSE[LICENSE]); licence/SPDX changes are owner-only (see link:.claude/CLAUDE.md[.claude/CLAUDE.md])
* **Enforcement** -- CI/CD workflows and pre-commit hooks

=== What actually blocks a merge

`main` is gated by the ruleset *main gate: append-only + required checks +
signatures + scanning*: 21 required status checks, branches required to be up to
date, and **no bypass actors**. Nothing merges without producing all 21.

That last clause is the one that is easy to lose, so it is worth stating what a
gate is *not*. A required check that no pull request can publish does not make
the gate stricter — it makes every pull request undecidable. On 2026-10-24 this
repository merged red repeatedly for exactly that reason, and not because a check
failed: pull request #1336 stood at 65 passing checks, a cleared review and
`mergeable=MERGEABLE` while `mergeStateStatus` stayed `BLOCKED`, because the
required context named the post-merge call site of a scan that runs pre-merge
under a different name. The only way through was the ruleset bypass, which
discards all 21 required checks in the same action.

Three things now keep that from recurring:

* *Producibility is a gate.*
  link:.github/workflows/required-contexts.yml[`required-contexts.yml`] runs
  link:scripts/check-required-contexts.sh[`scripts/check-required-contexts.sh`]
  on every pull request and weekly. It rejects undeclared findings:
  `PR-UNPRODUCIBLE`, `UNSATISFIABLE`, and `UNSATISFIED-RULE` for data-dependent
  rules such as `code_coverage` and `code_quality`. App-owned contexts are
  excluded from findings, and declared findings are permitted.
* *Exemptions are declared, dated and shrink-only.*
  link:.machine_readable/required-contexts-allow.txt[`required-contexts-allow.txt`]
  lists known-unsatisfiable requirements with a reason. Its two live entries
  declare the `code_quality` and `code_coverage` rules in ruleset `23787415`,
  pending Code Quality enablement and a successful coverage upload. An empty
  list is the goal; the gate warns when a listed entry stops
  appearing as a finding, so it cannot rot into a museum of stale exemptions.
  Silence is never achieved with `continue-on-error` or `|| true` — both were tried here and
  both produced an always-green job that reported a gate it never ran.
* *The repair is scripted.*
  link:scripts/fix-required-context-name.sh[`scripts/fix-required-context-name.sh`]
  repoints a single named context at a single named ruleset, refuses every state
  it cannot justify, and verifies the read-back. Branch protection is edited by
  a narrow instrument or not at all.

The full measurement, including the 3h20m of red `main` that motivated it, is in
link:docs/audits/audit-ci-context-producibility-2026-09-20.adoc[the context-producibility audit].

* `LICENSE.txt`
* `.github/FUNDING.yml`

All application launchers and desktop integrations must comply with the
link:docs/UX-standards/[E-Grade Launcher Standard]. This includes:

* No terminal wrapping for GUI/web applications
* Proper process management with `nohup`
* Self-diagnostic capabilities
* Clear user feedback
* Graceful error handling

== Usage

=== For New Hyperpolymath Projects

1. Copy governance templates to your repository
2. Create `<repo>_chora.deed` at the repo root, modelled on `rsr-template-repo_chora.deed` and checked with `deed_lint.js`; add `coordination.k9` and `*.k9.ncl` contracts where they apply (see <<Machine-Readable Metadata>>). Do not create `.a2ml` files
3. Add `Mustfile` and `justfile` (from hyperpolymath/mustfile)
4. Add enforcement workflows to `.github/workflows/`
5. Install pre-commit hook
6. Add language policy to `.claude/CLAUDE.md`

=== For Contributors

* Read the link:.claude/CLAUDE.md[Language Policy] before proposing code
* No TypeScript, Go, Python, Java, Kotlin, Swift, or Makefiles
* All source files must have SPDX headers
* Follow the template in `CONTRIBUTING.md` for your project

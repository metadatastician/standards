== Status

Stable — Version 1.2.0. Owner ruling D311 (2026-10-06) made the 1.1 line
canonical; rulings D317 and D318 made the 1.1.1 grammar patch; an owner
ruling of 2026-10-13 added the two optional sections of 1.2.0 below.

The normative grammar is
link:abnf/coordination-k9-grammar_v1.2.abnf[`coordination-k9-grammar_v1.2.abnf`].
The v1.1 file is kept, marked superseded, so that existing links resolve.
Where this prose, its examples or a generator disagree with the ABNF about
syntax, the ABNF wins.

Every example in this document parses under that ABNF. Read them closely:
`repo:`, `pattern:` and `languages:` items are bare tokens, while
`alternatives_rejected:` items are quoted strings. Blank lines appear
between sections, never inside one.

NOTE: *Line-length limit, 2026-11-12.* Owner ruling I4 caps every line at
998 octets (rule 14), so that the registered `8bit` encoding label is
exact. The version stays 1.2.0: no file in this repository came near the
limit, and the media type is not yet filed. A 1.1.1 file with a longer line
is not a 1.2.0 file.

NOTE: *Changes in 1.2.0.* Two optional sections, additive, so every 1.1.1
file is a 1.2.0 file: `build_commands` (the commands an agent may run, each
with its purpose) and `innervation` (the signals a repository emits and
responds to, and the local guards it enforces).

NOTE: *Changes in 1.1.1.* Two grammar fixes, both owner rulings of
2026-10-06. (1) D317: `languages:` items are indented one level deeper than
their key (four spaces), as every other list already was; 1.1.0 placed them
at the key's own indent. (2) D318: full-line `#` comments are permitted
between sections, as blank lines are. They are not permitted within a
section, and a `---` separator is still invalid.

== File Identity

[cols="1,3"]
|===
| Filename | `coordination.k9`
| Location | Repository root
| K9 Level | Kennel (pure data, no execution)
| Magic Number | `K9!` (mandatory first line)
| Media Type | `application/vnd.metadatastician.k9.coordination` (link:../docs/iana/application-vnd.metadatastician.k9.coordination-registration.txt[registration draft], not yet filed; distinct from `application/vnd.metadatastician.k9`, which is K9 SVC components)
| Line length | At most 998 octets per line, not counting the line end (rule 14)
| SPDX | `PMPL-1.0-or-later` (or project license)
|===

== Schema

=== Required Sections

==== `metadata`

Identity and versioning for the coordination file itself.

[source,yaml]
----
metadata:
  schema: k9-coordination
  schema_version: 1.2.0
  generated_by: k9-coordination-generator
  last_updated: 2026-04-03
----

==== `project`

Core project identity. Tells any arriving agent what this project IS.

[source,yaml]
----
project:
  name: "project-name"
  description: "One-line description"
  license: PMPL-1.0-or-later
  repo: hyperpolymath/project-name
  languages:
    - AffineScript
    - Rust
  build_system: just
  runtime: deno
----

==== `invariants`

Rules that MUST NOT be violated. Each invariant has an id, rule, and reason.

[source,yaml]
----
invariants:
  - id: no-typescript
    rule: "Do not introduce TypeScript files anywhere in this project"
    reason: "AffineScript is the chosen frontend language — this is deliberate"
    severity: critical
  - id: custom-runtime
    rule: "Do not replace the custom runtime in src/core/"
    reason: "18-module custom build — the off-the-shelf alternative was deliberately rejected"
    severity: critical
----

Severity levels: `critical` (never violate), `high` (ask user first),
`moderate` (prefer compliance).

=== Optional Sections

Optional sections appear in this fixed order, each at most once:
`build_commands` (between `project` and `invariants`), then after
`invariants`: `protected`, `architecture`, `innervation`, `do_not_create`,
`terminology`, `ecosystem`, `coordination`.

==== `build_commands` (1.2.0)

The commands an agent may run in this repository, each with its purpose. An
agent should prefer these to commands it infers.

[source,yaml]
----
build_commands:
  - command: "just build"
    purpose: "Build all sub-project artefacts"
  - command: "just test"
    purpose: "Run every sub-project test suite"
----

==== `protected`

Files and directories that are architecturally significant and must not be
deleted, reorganised, or replaced without explicit user approval.

[source,yaml]
----
protected:
  - path: src/core/
    reason: "Custom runtime — 18 modules"
  - path: .machine_readable/
    reason: "Canonical location for machine-readable state"
  - path: coordination.k9
    reason: "This file — source of truth for AI coordination"
----

==== `architecture`

Deliberate architectural decisions that may look wrong to an unfamiliar agent.

[source,yaml]
----
architecture:
  - id: gossamer-not-tauri
    decision: "Gossamer (Zig + WebKitGTK) is the desktop backend"
    reason: "Migrated from Tauri 2.0 — this is the intended direction"
    alternatives_rejected:
      - "Tauri"
      - "Electron"
      - "native GTK"
  - id: project-compiler-build
    decision: "Use the project-declared build command for the AffineScript frontend"
    reason: "Compiler setup is project-specific — follow build_commands rather than inferring tooling"
----

==== `innervation` (1.2.0)

How the repository takes part in the wider estate. `afferent` lists the
signals it emits and who consumes them; `efferent` the signals it responds
to, and whether the response fixes things itself; `reflex` the local guards
that need no central processing. Each subsection is optional, but the
section needs at least one.

[source,yaml]
----
innervation:
  afferent:
    - signal: "spec.updated"
      description: "A specification document changed"
      triggers_on: "push to spec/ directories"
      consumers:
        - hypatia
        - verisimdb
  efferent:
    - signal: "hypatia.finding"
      action: "Log the finding"
      auto_fix: false
  reflex:
    - trigger: "pre-commit"
      guard: "panic-attack assail"
      action: "Block the commit on critical findings"
----

`consumers` items are bare tokens, one per line; `auto_fix` is `true` or
`false`, unquoted.

==== `do_not_create`

Things that must NOT be introduced. Prevents well-meaning agents from
creating parallel systems.

[source,yaml]
----
do_not_create:
  - pattern: **/*.ts
    reason: "TypeScript is banned — use AffineScript"
  - pattern: Dockerfile
    reason: "Use Containerfile (Podman, not Docker)"
  - pattern: package-lock.json
    reason: "npm lock files banned — use deno.lock"
  - description: "REST API parallel to Groove endpoints"
    reason: "Groove is the inter-service protocol"
----

==== `terminology`

Correct terminology for this project. Prevents agents from using wrong names.

[source,yaml]
----
terminology:
  - correct: panels
    incorrect:
      - panes
      - tabs
      - windows
    context: "PanLL UI elements are always called panels"
----

==== `ecosystem`

How this project relates to others. Helps agents understand what NOT to
duplicate and where to look for related functionality.

[source,yaml]
----
ecosystem:
  depends_on:
    - name: gossamer
      role: "Desktop backend (WebKitGTK + Zig)"
    - name: verisimdb
      role: "Persistent storage layer"
  consumed_by:
    - name: idaptik
      role: "Uses PanLL as level editor"
  related:
    - name: typell
      role: "Type intelligence engine — cross-panel type checking"
----

==== `coordination` (Phase 2)

Active agent work tracking. Updated by agents or tooling.

[source,yaml]
----
coordination:
  active:
    - agent: claude
      area: "ABI layer + Groove endpoints"
      started: 2026-04-03
      status: in-progress
    - agent: gemini
      area: "Test coverage for auth module"
      started: 2026-04-02
      status: blocked
      blocker: "Waiting for upstream API key"
  completed:
    - agent: cursor
      area: "CSS layout refactor"
      completed: 2026-04-02
  available:
    - "Documentation for new API surface"
    - "Integration tests for Groove handlers"
----

== Validation Rules

The ABNF is normative; these rules summarise it (1–10) and add the schema
rules a grammar cannot express (11–14).

1. File MUST start with `K9!` on line 1, with no leading whitespace or BOM.
2. One or more `# SPDX-` header lines MUST immediately follow the magic line.
3. `metadata`, `project` and `invariants` MUST appear, in that order.
4. Optional sections MUST appear in the fixed order given above, each at
   most once. Every optional section needs at least one entry when present;
   `invariants` may be empty.
5. Indentation is exactly two spaces per level; tabs are invalid.
6. Blank lines and full-line `#` comments are permitted between sections,
   not within them. A `---` separator is invalid.
7. Keys and enumerated values are case-sensitive (RFC 7405 `%s`).
8. Strings are double-quoted and support only the escapes `\"`, `\\`,
   `\n` and `\t`.
9. `schema_version:` (and any `value`) may be a bare version such as
   `1.1.1`, unquoted.
10. Dates are ISO 8601 calendar dates (`2026-10-06`) or full RFC 3339
    date-times (`2026-10-06T12:00:00.5+01:00`). Line endings are LF or CRLF.
11. `metadata` MUST carry `schema: k9-coordination`.
12. Each invariant MUST have `id`, `rule` and `reason`; each protected
    entry MUST have `path` and `reason`.
13. Severity defaults to `critical` if omitted.
14. No line is longer than 998 octets, not counting its CR and LF. This
    is the RFC 5322 Section 2.1.1 bound, and it makes the registered
    `8bit` encoding label exact (RFC 2045 Section 2.8). The grammar states
    it in its header as a constraint on the whole file; ABNF cannot express
    it compactly. Owner ruling I4, 2026-11-12.

== Generator Behaviour

The generator reads `coordination.k9` and emits one file per supported AI tool.
All generated files:

1. Start with a comment indicating they were generated from `coordination.k9`
2. Include a "do not edit directly" warning
3. Render all sections as markdown appropriate for the target tool
4. Are idempotent — re-running overwrites with current state

Generated files SHOULD be committed to the repository so that AI tools
which read them on startup get the coordination context immediately.

== Relationship to Existing Files

`coordination.k9` does NOT replace:

* `<project>_chora.deed` — typed identity and descriptive state
  (descriptiles are its clauses, owner ruling D312); `project.deed_ref`
  links to it
* `.claude/CLAUDE.md` — can coexist; generated CLAUDE.md merges with existing

A2ML is retired (owner rulings D308, D313). A legacy
`0-AI-MANIFEST.a2ml` or `.machine_readable/*.a2ml` file is not
authoritative and is not a discovery path; agents discover
`coordination.k9` at the repository root.

= K9 conformance lane — tools
Campaign: standards#1058 · Ruling: D173 ·

== What lives here

[cols="1,3"]
|===
|`k9-validate.sh` |The canonical validator. The only place K9 rules are
*executed*; the contract file is where they are *stated*.
|`fixtures/valid/` |7 positive controls.
|`fixtures/invalid/` |22 negative controls. The load-bearing half.
|===

The local gate (`.githooks/validate-k9.sh`) and the CI gate
(`.github/workflows/k9-contractile.yml`) both call `k9-validate.sh`. Neither
owns a rule.

The hook's default layer is L1 (it must run on a machine with no toolchain);
the CI corpus step raises it with `K9_VALIDATE_LAYER=all`, because CI installs
the pinned `nickel` binary. Ledger entries stay advisory at either layer.

== Compact CI reports

link:CONFORMANCE-REPORTING.adoc[Conformance reporting] defines the evidence
schema, five-state verdicts, comparison rules and dated artifact layout.
`conformance-report.mjs` renders one updatable PR table with expandable findings;
`conformance-report.test.mjs` checks failure and missing-evidence behavior.
Consumers do not run that script: they call the reusable
`.github/workflows/k9-conformance.yml` at a pinned standards SHA, which runs
`k9-validate.sh` from that commit and renders the grid with
`scripts/k9-grid.sh` (see `docs/CONTRACTILE-DESCRIPTILE-VALIDATION.adoc`).

== Running it

[source,bash]
----
# 1. the validator's own assertions — run this first
./k9-validate.sh --self-test

# 2. the corpus
./k9-validate.sh --fixtures fixtures

# 3. with Nickel on PATH, every format layer must actually run
./k9-validate.sh --strict --fixtures fixtures

# 4. one file
./k9-validate.sh path/to/component.k9.ncl
./k9-validate.sh --json path/to/component.k9.ncl
----

Exit codes: `0` conforming · `1` violation · `2` usage error · `3` required
checks were SKIPPED under `--strict`.

== The four layers, and why the difference matters

[cols="1,2,3",options="header"]
|===
|Layer |Establishes |Needs
|L0 |the file *claims* to be K9 (bytes, licence, dialect) |nothing
|L1 |the pedigree fields are *written* |nothing
|L2 |the body *satisfies the contract* |`nickel`
|L3 |the signature *verifies* |an external verifier
|===

Each row is strictly weaker than the one below it, and the recurring defect in
this estate is a gate that reports the authority of a higher layer while doing
the work of a lower one. The two most expensive instances, both closed by this
lane:

* a Hunt gate satisfied by the *presence* of a `signature` field (§10.4 — only
  `'Verified` counts, and `'Present_Unverified` is false);
* a lexical pass reported as conformance (§12.3 — L1 is a screen, and a reader
  MUST NOT report conformance on L1 alone where Nickel is available).

A check that could not run is reported as `SKIPPED`, naming the rule and the
layer. It is never a pass, and `--strict` turns it into a failure.

== Negative controls

A validator that accepts everything passes every positive fixture, so a suite
of positives alone proves nothing. `fixtures/invalid/` is what shows the gate
can fire — standards#1058 says so directly: *"a grammar with no rejecting
validator is the same class of artefact"* as the gates that could never fire
(#49, #64).

Each negative fixture is named `L<layer>-<rule>-<reason>.k9.ncl`, and the
runner asserts three things:

. the file is rejected;
. it is rejected *by the rule its name claims*;
. it is rejected *at the layer its name claims*.

Assertions 2 and 3 are what stop a fixture from passing for the wrong reason.
A fixture that trips an unrelated earlier check still gets rejected, and a
runner that only checked rejection would report that as a pass while the rule
under test does nothing.

Coverage, measured: *21 of the 24* rules in the contract have a negative
control in `fixtures/invalid/` that names them. All 24 are exercised — the
other three cannot have a fixture, and each is instead asserted in
`--self-test` *to fire*, not merely described:

[horizontal]
`K9-C001` |No fixture can make a verifier appear, so `--self-test` drives it
with a stub. All three verdicts a host can reach are exercised ('Not_Run →
`'Present_Unverified`, accepted → `'Verified`, refused → `'Rejected`), **and so
is the consequence**: a refused signature must exit non-zero with verdict
`fail`. An error finding that left the exit status at 0 would let a host read
§9.4's Hunt precondition as advisory.
`K9-N002` |A self-check on the contract file itself, run before the contract
judges anything. `--self-test` points the validator at a deliberately broken
contract through the `K9_CONTRACT` seam and asserts the rule fires, that L2
then makes *no* `K9-N001` claim about the component (the contract's failure
must not be reported as the component's), and that the file still fails. With
no `nickel` binary it asserts the other half: skipped, never passed. This rule
fired four times during #1058 and had no control proving it still could.
`K9-E000` |A missing-path validation failure, not a conformance rule, and it cannot have a fixture
— the file would have to not exist. `--self-test` asserts a missing path raises
it and exits non-zero. It matters because "file not found" is the one finding a
gate can emit while checking nothing at all: a runner that mistook it for a
pass would report an empty corpus as conforming.

=== The two L2 controls

`L2-K9-N001-wrong-field-type.k9.ncl` and
`L2-K9-N001-two-segment-version.k9.ncl` are rejected *only* by Nickel:

* `allow_network = "yes"` is spelled correctly, sits at the right path and
  carries a value — it is just a `String` where the contract requires a `Bool`.
  L1 has no notion of a type.
* `schema_version = "1.0"` has the right major and only digits and dots, so L1's
  bounded screen accepts it. §5.2 requires a dot-*triple*, and it is the
  contract's `is_semver_of` that counts the segments.

Between them they are the argument for the layering. Without a `nickel` binary
the runner does not pretend to assert them: it verifies the half it *can* —
that they are lexically clean, which is the precondition for being an L2
control at all — reports `SKIP`, and `--strict` refuses the run outright.

They have already earned their place. The first CI runs with Nickel installed
had L2 calling `nickel typecheck` only, which Nickel's own CLI documents as
*"typechecks the program but does not run it"*. Contracts are applied when a
value flows through them, so the predicate behind `schema_version` never fired
and *both of these controls were accepted*. They are the reason L2 now
evaluates as well as typechecks (§12.2). A suite whose negative controls can
only pass would not have noticed.

=== The host-side mirrors

The closed leash set and the closed core capability set are each written down
twice: once in link:../spec/contract/k9_contract.ncl[`k9_contract.ncl`], which
is normative, and once in link:../leash.ncl[`leash.ncl`] and
link:../capabilities.ncl[`capabilities.ncl`], which carry the host-side
machinery — `detect_level`, `check_level`, the handshake records — that a
contract file has no business holding. The validator never loads those two.

`--self-test` therefore asserts the two copies agree, and pins each set in its
own right:

[horizontal]
`leash.ncl SecurityLevel mirrors k9_contract.ncl` |The enum literal against the
contract's `leash_levels`.
`capabilities.ncl core mirrors k9_contract.ncl` |The array literal against
`core_capabilities`, order included.
`the leash taxonomy is exactly three, closed (§7)` |So a fourth leash cannot
appear in the contract without a decision.
`hunt_preconditions is exactly the five, closed (§9.2)` |So Hunt cannot be
weakened by dropping a precondition. A valid signature alone was never
sufficient and this is one of the places that stops it becoming so by accident.

Every value is extracted from the enum and array literals, never from a
comment: rewriting the prose that documents a list must not be able to satisfy
the check that tests it. All four were mutation-tested — renaming a capability,
dropping `'Yard` from the enum, deleting `dry_run` from `hunt_preconditions`,
and adding a fourth leash each produce a FAIL.

== Byte-preserved fixtures

`L0-K9-E003-crlf.k9.ncl` exists to be rejected for its line endings.
`1-formats/k9/.gitattributes` carries `-text -eol` for it, because normalising
it on commit would delete the negative control while leaving the file behind —
and a suite whose negative control no longer fails is a suite that reports
green over nothing.

Corpus scans must skip `fixtures/` entirely, for the mirror-image reason: a
"fix" that made the negative controls pass would be a fix that broke the suite.
`.githooks/validate-k9.sh` excludes the directory.

== Adding a rule

. State it in link:../spec/K9-CONTRACT-SPEC.adoc[`K9-CONTRACT-SPEC.adoc`] with
  a rule id, and add it to the rule index (Appendix A). Rule ids are never
  renumbered; a withdrawn rule keeps its id.
. Encode it in link:../spec/contract/k9_contract.ncl[`k9_contract.ncl`] if it
  is semantic, or in `k9-validate.sh` if it is lexical — and say which layer it
  belongs to. A rule that cannot say is not ready.
. Add a negative control named for it, and assert it fires *at the layer you
  claimed*.
. If the rule duplicates a list already in `leash.ncl` or `capabilities.ncl`,
  add a `--self-test` mirror assertion so the duplication cannot drift. The two
  lists that exist today are already covered — see _The host-side mirrors_
  below — so this step is about the next one, not those.

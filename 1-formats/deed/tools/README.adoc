= DEED conformance lane — tools
Campaign: standards#837 · Grammar: link:../spec/abnf/deed.abnf[spec/abnf/deed.abnf (v1.5.0, normative)]

== The lane's one property

*Nothing invalid ever lands.* Every emitted deed passes the validator before
it may be written; every `.deed` committed in this repo is linted in CI.

== `deed_lint.js` — the validator

`deed_lint.js` runs under bun with zero dependencies, and it is the CI gate
(`.github/workflows/deed-conformance.yml`, callable from other repos via
`workflow_call`). Unit tests: `bun test 1-formats/deed/tools/`.

The Python linter `deed_lint.py` (frozen at deed.abnf v1.0.0) and the
Python translator `a2ml_to_deed.py` were deleted on 2026-11-13 (owner
ruling; D313, Python banned). Conversion of A2ML is kyX's first front end,
and the mapping specs in `../mappings/` stay the authority for where each
family's content goes.

Enforced rules:

* SPDX header required; one form; full input consumed
* doc-head whitelist (`estate-deed / repo-deed / estate-atlas-deed / praxis-deed`, and from v1.4.0 the J14 heads `contractile-deed / descriptile-deed / anchor-deed`)
* the J17 bang (v1.5.0): `!` after a separator, only on the `:id` of a top-level `(rule …)` in a `contractile-deed`
* `:schema-version` STRING exactly once (validator-level semantic, per grammar)
* filename ↔ doc-head dispatch with the exact-stem-first side condition
  (`estate_chora.deed` can never be a repo-deed; stems may contain dots —
  split on the final suffix only)
* booleans ONLY `#t`/`#f`; bare `true/false/yes/no` values rejected
* uuid5 literals `#u5"name"` — body is the RFC 4122 §4.3 name input, never hex
* uuid8 literals `#u8"domain:name"` — body is the ADR-008 profile C preimage;
  the domain before the first `:` must be non-empty printable ASCII
  (`#u7` and every other `#`-form is a parse error)
* strings: exactly four legal escapes (`\" \\ \n \t`); `\r`/`\uXXXX` are
  parse errors; raw control bytes rejected; spaces INSIDE symbols impossible
* separators are SP / line-end / comment ONLY — tabs are invalid everywhere
  (K9-consistent); bare CR rejected (CRLF or LF line-ends only)
* quoted values restricted to symbols and lists

Usage (the frozen Python implementation does *not* support the newer modes):

    bun deed_lint.js FILE.deed...
    bun deed_lint.js --self-test          # 14-case embedded corpus
    bun deed_lint.js --fixtures fixtures/ # valid/ must pass, invalid/ must fail

== `deed_lint.js --ast-json` — validated syntax for semantic consumers

    bun deed_lint.js --ast-json path/to/example_praxis.deed

Outputs one JSON object with `head` (the document kind) and `items` (the
ordered parser tree), and no success messages on stdout. A field is
`["field", "name", ["value-kind", value]]`; a clause is
`["clause", "name", [members...]]`. `integer` values retain their *exact
base-10 spelling as strings*, not floating-point JS numbers. Nested clauses,
string escapes and multiline fields are parsed by the canonical grammar,
not by line-shaped shell regexes.

Exit 0 means *grammar and filename dispatch* passed, **not** that a Mustfile,
Debtfile or claims deed has satisfied its domain invariants. Consumers MUST
check their expected clause types and counts (including a nonzero count),
mandatory fields, duplicates, types, enumerations and the applicable semantic
rules before reporting success. Missing files, malformed input or ambiguous
arguments produce a nonzero exit and *no JSON*. The tool does not execute
embedded commands. This is the shared parsing seam for the A2ML retirement
campaign (#837 and PR #1343), not a substitute for the existing policy gates.

== `deed_lint.js --mustfile-json` — the Mustfile check profile

    bun deed_lint.js --mustfile-json path/to/must_praxis.deed

Validates the entire praxis-deed and every `(check …)` clause against the
Mustfile profile, then emits a JSON array of `id`, `severity`, `discharge`
and `body` records. Empty check sets, duplicate IDs/fields, unexpected nested
clauses, unknown severities/discharge modes and hollow bodies are errors.
The profile is line-layout independent; it also rejects malformed DEED
*before* emitting any executable content.

It does not run shell commands. `scripts/check-mustfile-structure.sh` uses it
for DEED structure; `scripts/run-mustfile.sh` uses it to discharge each
`run` entry, reporting `verification` entries as MANUAL rather than claiming
they were executed. Those shell interfaces keep the legacy A2ML mode until
its downstream consumers are migrated. The DEED runner requires Bun and jq;
both are present in the repository's self-test workflow. Its regression
suite is `scripts/tests/check-mustfile-deed-test.sh`.

== `deed_lint.js --proof-receipt-json` — the proof-receipt profile

    bun deed_lint.js --proof-receipt-json path/to/proofs_praxis.deed

Validates a proof receipt (`:profile proof-receipt`, PROOF-POLICY §8.5.1)
and emits one JSON record. It holds `repository`, `source_commit`,
`trusted_base`, `echoes`, and `claims` with each claim's legs and receipts. Each claim's
Proof Witness Grade and foundation-diversity tag are *derived* from its legs
and receipts (§8.2, §8.3). A receipt whose recorded `:pwg` or
`:foundation-diverse` differs from the derived value is refused, because a
grade is derived, not asserted (§8.4). The vocabularies (§5 tokens, §2.2
states, routes, receipt states) are closed, and anything outside them is an
error. Unknown or duplicate fields, short commits, a missing Agda leg,
non-current receipts without a `:reason` and empty receipts fail closed, and
then no JSON is written.

Every current receipt carries `:inputs-sha256` and `(inputs-manifest …)`
(§8.5.1), and `(axioms …)` (§8.4). The reader rebuilds the manifest and
refuses a digest that is not its SHA-256. A receipt may also hold `(import …)` clauses
for pinned repositories it read, and a claim may hold negative `(control …)`
records (§8.5.4), which are never graded. A leg whose current receipt lists an axiom that is not disposition
`c` does not count. Top-level `(echo …)` records (§8.5.2) let a receipt
earned on a commit that a squash or rebase rewrote count toward `PWG-1` for
its image. The reader checks their form and consistency only. The git checks
of §8.5.3 belong to the gates: `scripts/check-proof-receipt.sh` does them, and
`scripts/proof-inputs-sha256.sh` computes the digests.

The worked examples are `fixtures/proof-receipt/example_praxis.deed` and
`fixtures/proof-receipt/echo_praxis.deed`, and the
tests are in `deed_lint.test.js` (`proof-receipt profile`). Mathesis's census
reads receipts through this reader.

== `deed_lint.js --egress` — the `(egress …)` clause profile

Checks what `spec/abnf/clauses/egress.abnf` adds to the grammar, on a file
that `deed_lint.js` already accepts: the field set and cardinality of each
`(job …)`, secret and endpoint syntax, the `:enforcement` symbols, and the
semantic rules the ABNF marks (no duplicates, no `GITHUB_TOKEN`, a
`secret:NAME` endpoint names a listed secret, ports in 1..65535, the clause
only at the top level). A deed with
no `(egress …)` clause passes. Prose: `spec/EGRESS-CLAUSE-SPEC.adoc`; decision:
ADR-009.

    bun deed_lint.js --egress FILE.deed...
    bun deed_lint.js --egress-fixtures fixtures/egress/

Its fixtures live in `fixtures/egress/`, not `fixtures/invalid/`, because
every invalid one is a grammatical deed: `deed_lint.test.js` asserts that
each passes `deed_lint` and fails only the profile.

== `deed_lint.js --anchor` — the `(anchor …)` clause profile (DRAFT)

Checks what `spec/abnf/clauses/anchor.abnf` adds to the grammar, on a file
that `deed_lint.js` already accepts: the member set of `(anchor …)` and of
each sub-clause, `:schema "hyperpolymath.anchor/1"` and a non-empty
`:authority` exactly once, value types, a three-segment `:version`, a
`:last-updated` that is a real calendar date, repo-relative
`(semantic-authority-files …)` paths, parents named only by an opaque
version 8 `#uuid` chora id (A1 rule V8), no parent twice and never the deed
itself (a legacy `#u8` or `#u5` `:repo-uuid` is compared by the profile C id
it names), and the clause only at the top level of a repo deed. A deed with
no `(anchor …)` clause passes. Prose: `docs/estate-reconciliation/A7-contractiles-descriptiles-anchor.adoc`,
proposed in standards#1489; ruling Q11 of the 2026-10-19 ultraplan.

    bun deed_lint.js --anchor FILE.deed...
    bun deed_lint.js --anchor --template rsr-template-repo_chora.deed
    bun deed_lint.js --anchor-fixtures fixtures/anchor/

`--template` marks the template's own deed, the one deed that may keep
repo-init's `{{TOKEN}}` placeholders; in any other deed a placeholder is an
error. In the fixture corpus, a file named `template-*` is checked in that
mode. `--anchor-fixtures` needs both `valid/` and `invalid/`, each with at
least one fixture: a missing or empty half exits 2, never OK.

The profile is a draft. CI gates only its own fixtures until the owner
ratifies A7; it does not yet run over a caller's committed deeds.

== `deed_lint.js --contractiles` — the `(contractiles …)` clause profile (DRAFT)

Checks what `spec/abnf/clauses/contractiles.abnf` adds to the grammar, on a
file that `deed_lint.js` already accepts (A7 8.2, tests YC01 to YC05):

* exactly one `(contractiles …)`, at the top level of a repo deed;
* each of the six verbs exactly once, as the symbols `intend`, `must`,
  `trust`, `adjust`, `dust` and `bust`;
* in each `(verb …)`, `:name`, `:declaration`, `:runner` and `:reality` each
  exactly once, and nothing else. A verdict, status or score is refused
  (J6, YC05);
* each path is exactly the one A7 8.2 names for its verb. For `must`, that is
  `.machine_readable/contractiles/must/Mustfile.deed`,
  `.machine_readable/contractiles/must/must.k9.ncl` and
  `.machine_readable/descriptiles/MUST.deed`. The verb `intend` takes
  `Intentfile.deed` and `INTENT.deed`;
* a `:contractiles_required` still written anywhere in the deed equals, as a
  set, the six directories `.machine_readable/contractiles/<verb>/` (J10,
  YC04).

A deed with no `(contractiles …)` clause passes.

    bun deed_lint.js --contractiles FILE.deed...
    bun deed_lint.js --contractiles --root REPO REPO/x_chora.deed
    bun deed_lint.js --contractiles-fixtures fixtures/contractiles/

That the eighteen named files exist is a repo check, not a lint check.
`--root` runs it against the repo root given (YC02, and YC03 for the
descriptile). `--contractiles-fixtures` needs both `valid/` and `invalid/`, as
for the anchor.

The profile is a draft. CI gates only its own fixtures until the owner
ratifies A7.

== `deed_lint.js --edict` — the edict form of a contractile-deed (DRAFT)

Checks a `<Verb>file.deed` (head `contractile-deed`, J14) against
`spec/abnf/clauses/edict.abnf` (A7 8.1, 8.4, 8.5). The rules it adds to the grammar:

* the form carries `:canonical-name`, `:of-chora` (an opaque version 8
  `#uuid`, J20) and `:verb`, each exactly once, and no `:beholding-chora`;
* `:verb` agrees with the file name. `Intentfile.deed` holds the verb `intend`
  (the A7 8.1 table);
* each `(rule …)` has `:id`, `:text`, `(applies-when …)` and `(requires …)`
  exactly once. The `:id` is unique in the file and is an A5 name segment;
* `!` follows only a rule's `:id`, and an `Intentfile` refuses it (8.4);
* `(applies-when …)` holds one selector: `(always)`, or `(identity …)`,
  `(profile …)`, `(capabilities …)` or `(context …)` with at least one field.
  `(clade …)` is refused, because no edict hangs off the clade (W10);
* `(requires …)` holds one requirement whose head is the deed's verb. Its
  `:witness` is the rule's own `:id` (J5), with exactly one of `:value`,
  `:at-least` and `:at-most`;
* `(envelope :for … :not-for … :tolerance …)` appears at most once, and only
  in a Bustfile (8.5). It holds at least one of the three fields, as
  `bust-envelope` requires, so an empty `(envelope)` is refused.

    bun deed_lint.js --edict Mustfile.deed
    bun deed_lint.js --edict-fixtures fixtures/edict/

The fixtures are one case per directory, `fixtures/edict/{valid,invalid}/<case>/<Verb>file.deed`,
because an edict's file name is fixed by its verb.

== `deed_lint.js --verb-descriptile` — the six verb descriptiles (DRAFT)

Checks `INTENT.deed`, `MUST.deed`, `TRUST.deed`, `ADJUST.deed`, `DUST.deed` and
`BUST.deed` (head `descriptile-deed`) against `spec/abnf/clauses/verb-descriptile.abnf`
(A7 7.1, 7.3, 8.5). The rules it adds to the grammar:

* the form carries `:canonical-name` and `:of-chora` (an opaque version 8
  `#uuid`, J20) exactly once, and no `:beholding-chora`;
* `:affirmed` (a real date) and `:affirmed-by` (a symbol) are required, and
  `:expires`, when present, is not before `:affirmed`. Affirmation is
  required by default (J4), and no relaxation can be written yet. Whether
  `:expires` is still in the future is the runner's check (YD06);
* the only clause is `(fact …)`: a `(rule …)` belongs in the verb's
  `<Verb>file.deed` (YF02);
* each fact has `:witnesses` (a rule `:id`, once per file, with
  `contractile/<verb>/<id>` at most 200 characters, A5 3.1) and `:evidence`
  (A2 D2's seven symbols), and an optional repo-relative `:source`;
* outside `BUST.deed` a fact has `:value`; in `BUST.deed` it has `:inherent`
  and `:residual` grades (`[ABCDEX][1-5]`), an optional `:justification`, and
  no `:value` (8.5). A residual `X1` blocks at the gate, not here;
* with `--root DIR`, every `:witnesses` names a rule of the verb's edict at
  `DIR/.machine_readable/contractiles/<verb>/<Verb>file.deed` (YD02), and
  `:of-chora` equals the `:repo-uuid` of the one `<repo>_chora.deed` in `DIR`
  (YD08). The chora deed carries `:repo-uuid` exactly once, and the edict's own
  `:of-chora` must equal it too, so facts are never joined against another
  repo's rules. A `--root` with no directory, or a `DIR` with no chora deed,
  is an error, never a skipped check;

    bun deed_lint.js --verb-descriptile MUST.deed [--root REPO]
    bun deed_lint.js --verb-descriptile-fixtures fixtures/verb-descriptile/

The fixtures are one case per directory,
`fixtures/verb-descriptile/{valid,invalid}/<case>/<VERB>.deed`. A case that
also holds the verb's `<Verb>file.deed` is checked against it (YD02), and one
that holds a `<repo>_chora.deed` has its `:of-chora` checked against that deed (YD08).

== `deed_lint.js --contractile-registry` — the `contractile` rule registry (A7 J13)

Generates the A5 registry `contractile_rules_praxis.deed` from a repo's six
edicts. All six `<Verb>file.deed` files are required; a missing one is an
error, so an accidental deletion cannot shrink the registry. There is one
`rule-def` per rule, with `:id "contractile/<verb>/<rule-id>"` and the rule's
`:text`. `:class gate` goes to every `must` rule and every rule marked `!`,
and `:class advisory` to the rest. Every entry gets `:excusable-at repo` and
`:scope-form exact-paths`, and a Bust rule also carries `:floor "A7 8.5"`.
`:beholding-chora` and the SPDX header are copied from the repo's own chora
deed.

A5 3.2 says an id is never deleted or reused. The generator therefore reads
the registry as last written: a rule that has left the edicts keeps its entry
with `:status retired`, and an edict that brings a retired id back is refused.
The edict form records no supersession, so a rename is a retirement plus a new
id, and `:supersedes` links are not generated. A hand deletion of a retired
entry is caught only against the base version (A5 R05), not by this tool.

The generator lives in `deed_lint.js` rather than its own script, so the
estate's count of hand-authored JavaScript does not grow
(`.github/no-js-baseline.txt`).

    bun deed_lint.js --contractile-registry --root REPO            # writes .machine_readable/contractiles/contractile_rules_praxis.deed
    bun deed_lint.js --contractile-registry --root REPO --check    # exit 1 when the committed registry is stale

Until `standards` has its own edicts (A7 M4), CI runs `--check` against the
fixture repo `fixtures/edict/registry/root/`.

== Fixtures

`fixtures/valid/` and `fixtures/invalid/` mirror the embedded self-test
corpus plus one real translated deed (`valid/rsr-template-repo_chora.deed`).
The fixtures that mirror the self-test corpus were generated from the
`_FIXTURES` table of the since-deleted `deed_lint.py`; the `#u8`/`#u7` fixtures (`uuid8-clade`,
`inu8-*`, `inu7`) are hand-written. Every invalid fixture must have an entry in
the `RULE` table of `deed_lint.test.js` naming the error it fails with.

== CI

`deed-conformance.yml` runs on any change touching `**.deed`, the grammar,
or these tools: self-test → fixtures → lint every committed `*.deed` file →
check every committed deed's `(egress …)` clause against the profile.

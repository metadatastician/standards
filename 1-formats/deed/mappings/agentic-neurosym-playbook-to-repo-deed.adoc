= Mapping spec — `AGENTIC.a2ml` / `NEUROSYM.a2ml` / `PLAYBOOK.a2ml` → `repo-deed` (family 4)
Campaign: standards#837 · Frame: link:README.adoc[mappings/README] ·
Status: RULED and applied (owner, 2026-10-27). The owner merged the first
translation under this spec, `standards_chora.deed` in standards#1356, and
on its review thread ruled the `(hooks …)` row below for a divergent
`[automation-hooks]` block. Earlier status: PROPOSAL pending owner review.

Three small contractile-profile surfaces, one spec: they share the same
shape (sparse sections, heavy booleans, `@profile` header). They are
behavioural permissions/config for agents and tooling — genuine repo state,
so `repo-deed` clauses are the correct home (not praxis-deed: no rules,
no priorities).

== 1. Source surface

`<repo>/.machine_readable/descriptiles/{AGENTIC,NEUROSYM,PLAYBOOK}.a2ml`,
plus older spellings. All three observed instances carry a leading
`@profile(id=a2ml/<name>)` annotation line (AGENTIC/PLAYBOOK confirmed;
NEUROSYM confirmed as `a2ml/neurosym`) — handled in §3. Translator refuses
any field not tabulated below (frame fail-closed rule).

== 2. Target form

AGENTIC translates into `.machine_readable/descriptiles/AGENTIC.deed`, a
`descriptile-deed` checked by `deed_lint.js --agentic` (A7 7.2, owner ruling
J33 of 2026-11-14): the members tabled below become its own members, and the
chora deed keeps no `(agentic …)` (a remaining one is warned for one release,
then refused in strict mode, A7 YF05). NEUROSYM likewise translates into
`.machine_readable/descriptiles/NEUROSYM.deed`, checked by
`deed_lint.js --neurosym` (owner ruling J35 of 2026-11-15; a chora
`(neurosym …)` is warned, then refused, A7 YF06). PLAYBOOK still translates
into a `(playbook …)` clause on the repo's single
`<canonical-name>_chora.deed` (same deed as families 1–2), until its own A7
module lands.

**D4-1 (decision record): comment-carried constraints are TEMPLATE CANON,
not per-repo state.** In rsr (and therefore in every rsr-descended repo) the
`[agent-constraints]` and `[automation-hooks]` sections carry their entire
content as a2ml *comments* — the banned-language list, the never-relicense
rules, and the on-enter/on-exit/on-commit protocol. Translating would
silently drop load-bearing behaviour, so it does not happen silently:
these blocks are identical template-boilerplate across the fleet, which
makes them *derivable from canon* — their home is the standards repo's
`.machine_readable/agent_instructions/` surface (already canonical), and
deeds carry only the `(methodology …)` pointer fields above. This is the
derivable doctrine applied to prose, recorded here so no future
translation PR "discovers" it afresh. If a repo ever DIVERGES from the
canon block, diff-detection at translate time (the tool hashes the
comment block against canon) fails closed and the divergent file earns
its own table rows.

== 4. Provenance & validation (extends P-1..P-8)

* **P-9 (profile literal):** each emitted deed's profile string equals the
  source `@profile(id=…)` payload byte-for-byte inside the quotes — the
  conformance lane checks for exactly one value estate-wide
  (`a2ml/playbook`, section 5) and any second string in that position is a propagation
  bug, flagged automatically. `a2ml/agentic` and `a2ml/neurosym` are not
  translated (J34, J36), so they never appear in a new deed. The check reads
  the target forms only: a `(profile …)` nested in a chora `(agentic …)` or
  `(neurosym …)` that YF05 or YF06 still permits for one release is a legacy
  form, reported by those rules and not counted here.
* **P-2a (table-closed):** applies per the frame; PLAYBOOK populated
  sections and NEUROSYM rule/config content fail closed for table
  extension rather than translate by guess.
* Boolean transform is total here (14 of the boolean-carrying fields in
  the recon): the checker asserts ZERO literal `true`/`false` tokens in
  these three clauses.

== 5. Acceptance greps

Each check runs over a directory of repo checkouts, `$ESTATE/<repo>/`, and
reads only each repo's canonical paths: its root `*_chora.deed` and its
`.machine_readable/descriptiles/` deeds. A recursive search would also count
fixtures and examples, such as `standards`' own
`1-formats/deed/tools/fixtures/…/AGENTIC.deed`, as repos.

* *Integrity preserved, per repo.* The number of repos with
  `:allow-silent-skip #f` in a canonical deed equals the number with
  `allow-silent-skip = false` in the old a2ml corpus. Same for the `#t`
  fields: all five integrity axioms are count-preserved per repo.
+
[source,bash]
----
for r in "$ESTATE"/*/; do
  n=$(grep -l ':allow-silent-skip #f' "$r"*_chora.deed \
        "$r".machine_readable/descriptiles/AGENTIC.deed 2>/dev/null | wc -l)
  [ "$n" -ge 1 ] && echo "$r"
  [ "$n" -ge 2 ] && echo "both forms: $r" >&2
done | wc -l
----
+
The integrity members live in `AGENTIC.deed` (J33). The chora pattern
counts a repo whose `(agentic …)` is still in its chora during the YF05
window. Each repo counts once however many of its files match, so a repo
with both forms cannot hide a repo whose translation is missing. A repo with
both forms is a defect, and the loop names it on standard error.
* *Profile strings, target forms only (P-9).* Over every repo, the distinct
  `:id` values of a `(profile …)` directly inside a chora `(playbook …)` are
  exactly `a2ml/playbook`. The check reads the deed's validated parse, not
  its text: a grep cannot tell which clause a `(profile …)` sits in, and a
  transitioning chora such as `standards_chora.deed` still holds the legacy
  `(agentic (profile …))` and `(neurosym (profile …))` that YF05 and YF06
  permit for one release. No `AGENTIC.deed` or `NEUROSYM.deed` carries a
  profile at all: `--agentic` and `--neurosym` refuse one (J34, J36).
+
[source,bash]
----
for r in "$ESTATE"/*/; do
  for d in "$r"*_chora.deed; do
    [ -f "$d" ] || continue
    bun 1-formats/deed/tools/deed_lint.js --ast-json "$d" | jq -r '
      .. | arrays | select(.[0] == "clause" and .[1] == "playbook")
      | .[2][] | select(.[0] == "clause" and .[1] == "profile")
      | .[2][] | select(.[0] == "field" and .[1] == "id") | .[2][1]'
  done
done | sort -u
----
* `scan-depth` symbols are exactly from the closed three-set (validator,
  not eyeballs).
* `:report-format` strings are exactly from the closed four-set `json text
  github sarif` (validator: `deed_lint.js --neurosym` refuses any other
  value, so no translated deed carries a retired format).

== 6. Per-bot directive files → `(bot-directives …)`

Owner rulings 2026-11-13: a bot with no directives runs its full suite
(panicbot runs the whole panic-attack suite); a directive that only denies
means "everything except these"; a dynamic mode takes its target from the
directives. The §3 `instructions-dir` pointer names a directory; this section
gives the facts inside it a deed home, because no new fact may be written to a
`.a2ml` file.

=== Source surface

`<repo>/.machine_readable/bot_directives/<bot>.a2ml`, one per bot (legacy).

=== Target form

One top-level clause on the repo deed, with one `(bot …)` per bot:

[source]
----
(bot-directives
  (bot :name panicbot
    :allow (assail assay diagnostics)
    :deny (assault ambush)
    (target :build "cargo build --release" :program "target/release/foo")
    (config :min-severity low :timeout-seconds 300)))
----

*Grammar-forced deviation.* The ruled shape was `(bot panicbot …)`. In
`deed.abnf` a clause is `"(" symbol *(token-sep (field / clause))`, so a bare
symbol after the clause name is not a legal member. The bot's name is
therefore the field `:name`, which comes first by convention. The deed linter
refuses the bare form (`fixtures/invalid/inbot-bare-name_chora.deed`).

=== Field table

[cols="2,3,4"]
|===
| source / meaning | deed path | transform

| the `<bot>` file name | `(bot :name <bot>)` | SYMBOL. Repeatable, one `(bot …)` per bot; a bot named twice is a conflict, not a merge.
| `allow` | `(bot … :allow (<mode> …))` | list of SYMBOLs. Optional; absent means the bot's full suite.
| `deny` | `(bot … :deny (<mode> …))` | list of SYMBOLs. Optional. Narrows the suite; deny wins over allow. A `(bot …)` with `:deny` and no `:allow` means everything except those modes.
| `[config] min-severity` | `(bot … (config :min-severity low))` | SYMBOL verbatim.
| `[config] timeout-seconds` | `(bot … (config :timeout-seconds 300))` | INTEGER.
| (new; no legacy key) rhodibot's community-document format | `(bot :name rhodibot (config :community-doc-format md))` | SYMBOL, `adoc` or `md`; absent means `adoc`. rhodibot only. It sets which form of `CONTRIBUTING` and `CODE_OF_CONDUCT` rhodibot names in a suggestion and would create; rhodibot accepts either file that is present, whatever the value. Owner ruling of 2026-11-15 (by selector, relayed by SysArch): "make it toggleable but note in my repos it is almost always adoc - and in any case, bot_directive allows per repo exceptions".
| (new; no legacy key) the dynamic-mode target | `(bot … (target :build "…" :program "…"))` | optional. Absent means dynamic modes report `not_applicable "no target declared"`. `:program` is a STRING path relative to the repo root and MUST resolve inside it (no leading `/`, no `..` escape, no symlink out). `:build` is a STRING shell command and runs only in an unprivileged job.
|===

Any other legacy key fails closed (frame rule P-2a), not translated by guess.
The grammar cannot express the `:program` containment or the allow/deny
precedence; the consuming bot enforces both, and the linter checks only that
the clause parses.

=== Read order

A bot reads the `(bot-directives …)` clause first. It reads the legacy
`.a2ml` file second, read-only, for repos not yet migrated. It never writes a
legacy file.

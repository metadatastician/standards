= Mapping spec — `rsr-criteria-v2.a2ml` → `praxis-deed` (`:profile rsr-criteria`)
Campaign: standards#837 · Frame: link:README.adoc[mappings/README] ·
Clause grammar: link:../spec/abnf/clauses/rsr-criteria.abnf[`clauses/rsr-criteria.abnf`] (DRAFT v0.1.0) ·
Status: **RULED (owner, 2026-11-15; §10).** Nothing is translated by this spec yet.

This spec is the authority under which kyX's A2ML front end (D313; ULTRAPLAN
P2.5) translates the RSR v2 criteria catalogue, the last canon artefact still
held in A2ML. It closes the canon-lockstep row of
`docs/estate-reconciliation/A7-contractiles-descriptiles-anchor.adoc` §10:
"A criteria praxis deed under a mapping spec written by kyX's front end
(D313). Not hand-converted." It authorises no hand conversion. The worked
translation in §6 is an abridged illustration, as in the other specs here.

The translator fails closed (owner ruling 2026-11-14): a table, key or value
shape that §3 does not list is refused with its line number. When the source
grows a field, this table is extended first. A field is never dropped with a
ledger entry.

== 2. Target deed form

[source]
----
0-canon/rsr/rsr-criteria-v2_praxis.deed
----

`praxis-deed` head, by the `<stem>_praxis.deed` dispatch row. The stem is
**`rsr-criteria-v2`**, and the head's `:canonical-name` is the same string.

* *Why the stem keeps `-v2`.* RSR-SPEC-v2 §8 freezes a major by copying its
  catalogue to `archive/rsr-criteria-vN…` and pinning its hash, so the major
  is part of the artefact's identity, and two majors must coexist under
  `0-canon/rsr/`. The scorecard profile already names the catalogue
  `rsr-criteria-v2` (`:spec rsr-criteria-v2`, ratified 2026-11-14), so the
  scorecard's `:spec`, the catalogue's `:canonical-name` and its file stem
  are one string. `rsr-criteria-v2.deed` would dispatch to nothing and be
  refused at line 1 (§5, M1).
* *Why `praxis-deed` and not `repo-deed`.* The catalogue is canon law: what a
  conforming repository must carry and how the oracle scores it. It is not the
  identity of any repository (a chora deed), not content organisation
  (`CLADE.deed`), and not registry. The estate's other two machine-read
  verification records, the proof receipt and the RSR scorecard, are already
  praxis-deed profiles selected by `:profile`. The catalogue is the input the
  scorecard is scored against, so it takes the same form beside it, with
  `:profile rsr-criteria`.
* *Why there is no `:priority`.* Nothing in this source is a first-match
  ladder. Scoring is a weighted sum over the applicable set, a tier is the
  highest whose inclusive threshold is met, and categories and criteria carry
  their own ids. Order is not semantic here, and none is faked.

=== Head

[source]
----
(praxis-deed
  :schema-version  "1.0.0"                  ; REQUIRED, exactly once
  :canonical-name  "rsr-criteria-v2"        ; REQUIRED; = file stem
  :profile         rsr-criteria             ; selects clauses/rsr-criteria.abnf
  :beholding-chora #uuid"0889b37b-defb-831f-973c-e119500db00e"
  (rsr-criteria …))                         ; the one clause
----

`:beholding-chora` is copied verbatim from `standards_chora.deed` (the estate
chora id the launcher praxis deed also carries). kyX reads it from that deed
and never mints or re-derives it (U1). A `#u5` literal is refused (S2).

| `:supersedes` | the prior catalogue major | `"1.0.0"`, verbatim

== 3. Field table

`→` left: the A2ML surface. Right: the deed path, its value type and the
transform. "verbatim" means the string's bytes are carried unchanged; the
source contains no `"` or `\` inside a string, so no escape is introduced.
All paths below are inside the one `(rsr-criteria …)` clause unless they are
head fields.

[cols="2,3,4"]
|===
| a2ml surface | deed path | transform / type

3+| *Head (new; no source field)*

| — | `:schema-version` | STRING `"1.0.0"`
| — | `:canonical-name` | STRING `"rsr-criteria-v"` + MAJOR of `[meta] version`: `"rsr-criteria-v2"`. Derived, and checked against the file stem
| — | `:profile` | SYMBOL `rsr-criteria`
| — | `:beholding-chora` | `#uuid"…"` copied from `standards_chora.deed :beholding-chora`

3+| *`[meta]` → fields of `(rsr-criteria …)`*

| `spec` | `:spec-family` | enum → SYMBOL `rhodium-standard-repositories` (closed set of one). ⚠ **renamed**: the scorecard's `:spec` names the catalogue (`rsr-criteria-v2`), so carrying `spec` under that keyword would give it a second meaning. `spec-family` is canon.lock's own name for this value
| `version` | `:spec-version` | STRING, semver with optional pre-release (`rc-semver`); written "2.1.1-draft" for this translation (Q5). The scorecard copies this string into its own `:spec-version`
| `status` | `:status` | enum → SYMBOL, closed set `draft stable`

== 4. Drop doctrine

* **Nothing that is a field is dropped, except `dialect`** (§3, Q8), and its
  value is checked before it is consumed. No string is reworded, even where
  it is now wrong (§9): translation carries the law as it stands, and
  changing the law is a canon change of its own (Q4).
* **Two keywords are renamed, no values are.** `spec` → `:spec-family` and
  `template_ref` → `:template-ref`. A consumer grepping the deed for
  `template_ref` will not find it, by design. The criterion's other six
  keywords keep their source names.
* **Comments are split by class** (proposal; the owner rules in Q2):
** *Kept as `;` comments*, because they state rules no field encodes:
   line 51 "Thresholds are inclusive lower bounds"; line 55 "Gold + the
   rhodium-only exemplary criteria (those with tier = "rhodium")"; line 22
   "MUST NOT be cited as ratified until §Ratification passes"; lines 261–262
   "weights are the per-category maxima … informative, not a gate".
** *Dropped as instructional prose* (it lives in RSR-SPEC-v2, which is the
   prose authority): the header narrative, lines 3–17 (but see Q3 for the
   SSOT claim it makes); the section explainers at lines 41, 50, 59, 68–69;
   the field glossary at lines 81–91 (the clause grammar is now that
   glossary); the inline `# draft | stable` vocabulary (the grammar's
   `rc-status` states it); the inline remarks at lines 26–27.
** *Dropped as duplicated record*: the 2.1.0-draft change note at lines
   28–38, which canon.lock's 2026-09-19 MINOR 2.0.4 → 2.1.0 entry also
   records with the same owner ruling (Q6).
** *Dropped as wrong arithmetic in prose*: line 82–83 "Weights sum to 100"
   (they sum to 88, as `[weights-check]` itself says) and line 260's sum
   line (`:sum-declared` carries it and is checked). Recorded in §9.
* **Nothing is dropped for being empty.** The source has no empty tables.

== 5. Provenance & validation

* **P-1 (source must parse first).** kyX reads the source with its record-dialect
  (TOML-shaped) reader, never with `grep`: the criteria are inline tables
  whose `desc` strings contain commas, so a line scrape splits them wrongly
  (this spec's own first census regex did exactly that).
* **P-2 (table-closed).** Any table, key, or value shape not in §3 is refused
  with its line number, and nothing is written. Value shapes are part of the
  table: a `tier` outside `crit-tier`, a `status` outside `draft stable`, a
  non-integer `weight`, or a `dialect` other than `"a2ml-record"` are refused.
* **P-3 (round trip).** For each of the 78 criteria, each of the seven values
  in the deed equals the source value once both are decoded: a string's
  decoded characters equal the source string's; a SYMBOL (`tier`) equals the
  characters of the source string it was converted from, after that string
  was checked against its closed set; an INTEGER equals the source integer.
  The counts in §3.1 hold too. The translator asserts this before writing.
* **P-4 (output must parse as DEED and as the profile).**
  `bun 1-formats/deed/tools/deed_lint.js 0-canon/rsr/rsr-criteria-v2_praxis.deed`
  ⇒ `OK`, and the clause parses as `rsr-criteria-clause` of
  `clauses/rsr-criteria.abnf` under the apg-js differential
  (`tools/deed-abnf-differential`, which would add the module to its compile
  list). The SEMANTIC notes of the module need a validator flag,
  `deed_lint.js --rsr-criteria [--root DIR]`, with valid and invalid
  fixtures, before the deed is relied on. Not written by this spec.
* **P-5 (mutants must die).** The lane carries at least these, each expected
  to fail: M1 the file named `rsr-criteria-v2.deed` (dispatch, line 1); M2 a
  `key = value` line; M3 a tab separator; M4 bare `true`; M5 no
  `:schema-version`; M6 `:status "draft"` (a string where the profile wants a
  symbol); M7 a duplicate criterion `:id`; M8 `:sum-declared` not equal to the
  weights' sum; M9 a criterion missing `:detect`. M1, M2 and M6 were run on
  the §6 example (results there); M7 to M9 need `--rsr-criteria`.
* **P-6 (licence lines).** The deed's header is the source's two SPDX lines,
  verbatim (`MPL-2.0` and the FileCopyrightText line). The translation
  chooses no licence and changes none.
* **P-7 (ids).** `:beholding-chora` is read from `standards_chora.deed`; the
  translator mints nothing.
* **P-8 (line cap).** No deed line exceeds 998 octets. The longest source
  value (criterion 5.2.6's `desc`, about 230 B) fits; the translator writes
  one field per line where a criterion line would pass the cap.
* **P-9 (the source is removed and stays recoverable).** In the change that
  lands the deed, `0-canon/rsr/rsr-criteria-v2.a2ml` is deleted, its ledger
  row is removed, and the deed takes the `criteria` slot in `canon.lock`
  (§7). Leaving both would be two sources of one law. The input stays
  addressable as blob `6fe48c66…` (27,263 B).

== 6. Worked translation (abridged: 2 of 11 categories, 4 of 78 criteria)

The block below is the whole example file. Save it as
`rsr-criteria-v2_praxis.deed` to rerun the results that follow. It was
hand-written to test this spec and the grammar, and is not the translation.

[source]
----
;; SPDX-License-Identifier: MPL-2.0
;; SPDX-FileCopyrightText: 2026 Jonathan D.A. Jewell (hyperpolymath) <j.d.a.jewell@open.ac.uk>
;;
;; ILLUSTRATIVE, ABRIDGED: 2 of 11 categories and 4 of 78 criteria, hand-written
;; to show that the draft mapping spec is complete and that the draft clause
;; grammar admits its output. It is not the translation; kyX emits that.
;; Translated from 0-canon/rsr/rsr-criteria-v2.a2ml (sha256 6a5aa885…) under
;; 1-formats/deed/mappings/rsr-criteria-to-praxis-deed.adoc.
(praxis-deed
  :schema-version "1.0.0"
  :canonical-name "rsr-criteria-v2"
  :profile rsr-criteria
  :beholding-chora #uuid"0889b37b-defb-831f-973c-e119500db00e"
  (rsr-criteria
    :spec-family rhodium-standard-repositories
    :spec-version "2.1.1-draft"
    :status draft
    :supersedes "1.0.0"
    :date "2026-09-19"
    :authority "RSR-SPEC-v2.adoc"
    :normative-oracle "hypatia:rsr-conformance"
    (versioning
      :model semver-with-errata
      :rule-major "A MAJOR bump is an era change: it MAY remove or redefine criteria and MAY move a criterion between tiers. Cutting a major freezes the prior major's rsr-criteria as an immutable, hash-pinned artefact under archive/."
      :rule-minor "A MINOR bump MAY ADD criteria or ADD a capability gate, but MUST NOT make a previously-conforming repo non-conforming at the same tier. Additive only."
      :rule-patch "A PATCH bump is editorial (wording, detection-rule id corrections, template_ref fixes) with no criteria-set change."
      :freeze-mechanism "A released major is frozen by pinning this file's byte-hash in .machine_readable/REGISTRY.a2ml (or the spec's own VERSIONS ledger), NOT by a prose 'FROZEN' banner. A freeze guard in CI (see [oracle].freeze-guard) fails any PR that mutates a frozen major's criteria file."
      :errata "Corrections that do not change criteria semantics are recorded in RSR-SPEC-v2.adoc Appendix E (Errata) and shipped as PATCH bumps.")
    (tiers
      ; Thresholds are inclusive lower bounds.
      :bronze 75
      :silver 90
      :gold 100
      ; Gold + the rhodium-only exemplary criteria (those with :tier rhodium).
      :rhodium 100
      :scale "X F E D C B A maps onto the readiness-grade scale; RSR tiers are the repo-shape projection (Bronze~C, Silver~B, Gold~A, Rhodium~A+).")
    (scoring
      :applicable-set "A criterion is APPLICABLE to a repo iff its `gate` is `universal` OR the repo's .machine_readable/rsr-profile.a2ml declares the gating capability (per 0-canon/TEMPLATE-APPLICABILITY-POLICY.adoc). Non-applicable criteria are scored `na` and excluded from the denominator."
      :denominator "sum of weights of APPLICABLE criteria"
      :numerator "sum of weights of APPLICABLE criteria whose `detect` returns pass"
      :partial "A criterion MAY return `partial` (e.g. some but not all files present); partial contributes half its weight and is reported explicitly."
      :na-honesty "A repo MUST NOT reach a tier by declaring away (via rsr-profile) a capability it actually has. hypatia cross-checks declared capabilities against detected ones (structural_drift) and flags under-declaration as :review."
      :report "The oracle writes a per-repo scorecard to verisim-data (.machine_readable/scorecards/<repo>.scorecard.a2ml shape) with per-criterion verdicts, the applicable set, and the resulting tier.")
    (oracle
      :normative "hypatia rule family `rsr-conformance` (to be implemented; consumes THIS file). hypatia is the estate scanner and already writes scorecards to verisim-data, so it is the natural oracle."

== 7. `canon.lock` and consumer migration (recorded here; not executed)

  so the `criteria` sha256 changes from `6a5aa885…` to the deed's. kyX's
  output must be deterministic so that this hash is reproducible from the
  source blob and the pinned kyX commit. rsr-template-repo's `(canon …)` takes
  the new `:criteria-sha256` and `:version` (with `:proposed-by` naming the
  standards PR while it is open), then every minted repo's pin follows
  (kyx_chora.deed carries two). `tests/workflows/canon_pin_check_test.sh`
  updates its fixture path.

== 1. Summary

* The metric is the number of commits that touch a unit in the last 90 days, in 4 bands: hot (20 or more), warm (5 to 19), cool (at least 1 in 180 days) and cold (none in 180 days) [O]. The unit is a `standards-map.toml` entry, with `mixed` entries split by subdirectory.
* Every one of the 3,146 tracked files already falls under a map entry [M]. A6 does not add a map. It adds a rate and a destination to the one that exists.
* Hot machinery goes to the homes that A3 to A5 name: checks and reusable workflows to `proven-cicd`; ruleset, settings and apply tooling to `git-logistics-office`; rules to `hypatia` (held, see H11); deed and k9 specifications to their own repos [O]. The operations diary goes to `metadatastician-governance` [O].
* A first-pass set of 10 ordered rules assigns 436 files to a destination outside `standards` and keeps 1,519 files as canon and as the repo's own working files, the 3 deprecated reusables among them until they are retired. The 1,191 archive files stay (section 6.1).
* The first pass does not make `standards` quiet. 75% of the commits of the last 90 days still touch a file that stays [M]. The activity that stays is mainly the repo's own working files, not the canon (section 5).
* Only 2 of the 70 canonical entries move: `1-formats/deed` and `2-protocols/k9-coordination`, both already ruled in the plan [M].
* A move is one rule group per PR: a signed squash-import into the destination with a link back to the `standards` commit, a pointer left behind, the map and `canon.lock` updated in the same commit. No sweep, no bulk move.

== 3. The metric

=== 3.1 Definition [O]

For a unit `U` and a date `T`:

----
rate90(U, T) = number of commits c with date(c) in (T - 90 days, T] such that c changes a file that is in U at T
rate180(U, T) likewise over 180 days
band(U, T) = hot if rate90 >= 20; warm if 5 <= rate90 <= 19; cool if rate90 < 5 and rate180 >= 1; cold if rate180 = 0
----

* A commit counts once for a unit, however many files of the unit it changes.
* Only files that still exist at `T` count. A file that was deleted or moved out does not make its old unit look active.
* Commits by bots are counted. They are under 5% [M] and a rule that depends on author names adds fragility.
* History before 2025-12-15 does not exist in this clone [M]. A band for a unit younger than 180 days uses what exists.

=== 3.2 Unit

The unit is a map entry. A file belongs to the entry with the longest `from` prefix that matches it [M: the rule I used; no file is unmatched]. An entry with `kind = mixed` is split by its subdirectories into units before banding (decision H4). Today the one such entry is `docs`.

=== 3.3 Why the unit is not a directory or a file

A district entry such as `1-formats` contains children that have their own entries (`1-formats/deed/` is hot at 49 and the rest of the district only 34). A file-level rate is noisy for a single file that was touched once. The map entry is the unit the estate already maintains, gates and links, so the rate attaches to something that has an owner and a gate.

== 6. Moves

=== 6.1 What does not move

The archive stays and is not edited. A move never touches a licence file, an SPDX header or a licence text: the import copies each file byte for byte, and a licence issue found during a move is flagged and left [M: estate rule, `standards/.claude/CLAUDE.md`].

=== 6.2 The mechanism of one move

A move is one rule group (or one map entry) per pull request, with these steps in order:

. *Plan.* The generated table (7.2) lists the exact files of the group, their destination and their inbound references (links, `uses:`, `canon.lock`, map rows, and scripts that read a file by path).
. *Import.* The destination repo receives the files as one signed squash-import commit. The message links to the `standards` commit that the files came from, and a tag or link back to that SHA is recorded [R: #1234 triage]. History stays in `standards`. No file is rewritten and no history is rewritten.
. *Pointer.* In `standards`, each moved directory keeps one `POINTER.adoc` naming the destination, the import commit and the date [M: `k9-svc` precedent]. The pointer resolves only the directory path, not the files below it. A moved single file leaves no pointer only when the inbound-reference list shows no link, `uses:`, map row or script that reads it by path. A script that reads a moved file by path (for example the scripts that read `deed.abnf`) is changed in the same PR or the file stays.
. *Map.* `standards-map.toml`: the entry's `target` becomes `-> <repo>`, and the entry stays until the files are removed; the Gate D bidirectional check keeps passing.
. *Lock.* If the group contains a hash-pinned artefact, `canon.lock` is bumped in the same commit [M: Gate A assertion 2]. The groups of section 4.1 contain none, because the pinned artefacts stay (H6).
. *Remove.* A second commit in `standards` removes the files after the destination has run for one cycle with the files in place and its own gates green. Every moved source file is frozen from the import to the removal. Before removal each file is compared with its imported revision; a file that changed in `standards` after the import is not removed, and is re-imported first.
. *Verify.* Byte equality of source and destination files; the link-rot guard reports no new BROKEN line; Gate D, Gate A and the canon lockstep pass.

=== 6.3 Callers that pin `standards`

Callers pin a reusable workflow at a full SHA [M]. The old file stays at that SHA in `standards` history, so a pinned caller keeps working. New callers pin the `proven-cicd` copy (A3). A6 requires no re-pin of any caller and measures the residual by the staleness of pins, not by forcing them. The moved reusable workflows are not edited in `standards` after the import: the `standards` copy is frozen until the pointer replaces it.

== 8. Laws

[cols="1,4"]
|===
| Law | Statement

| CL1 | Total assignment. Every tracked file has exactly one destination. No file has none, no file has two.
| CL2 | Bidirectional map. Every file belongs to a map entry and every map entry owns a file or is marked empty. Gate D keeps passing after every move.
| CL3 | Byte equality. A file in the destination after a move is byte-equal to its source at the import commit.
| CL4 | Pinned artefacts. A move of a hash-pinned artefact bumps `canon.lock` in the same commit. A move that leaves `canon.lock` stale fails Gate A.
| CL5 | No dangling reference. After a move, no link, `uses:`, map row or script names a path that no longer resolves. A `POINTER.adoc` resolves its directory path only, never a file below it.
| CL6 | Frozen archive. The archive is byte-equal before and after every move.
| CL7 | No licence edit. A move changes no licence file, SPDX header or licence text.
| CL8 | Reproducible metric. The rate and band of every unit are recomputable from `git log` and the map at a given commit, with no other input.
| CL9 | Canon stays canon. Only entries ruled by the owner leave while `canonical = true`. Today only `1-formats/deed` and `2-protocols/k9-coordination`.
| CL10 | One group at a time. No move starts while another group's PR is open.
|===

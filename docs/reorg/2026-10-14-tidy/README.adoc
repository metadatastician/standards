This pack is the deep dive the owner asked for on 2026-10-14: what the
`standards` repository is, why it is hard to read, what its 220 open
issues actually ask for once read literally, sensibly and for the mischief
they were filed against, how it is wired to the seven neighbouring
repositories, and a phased plan that cheaper models can execute packet

measured on the tree at `7d2041a2` (main, 2026-10-14) and every ruling
cited is on #787 or #1234.

== Summary

* The repository is a *canon* (specs, policies, grammars, gates) that has
  absorbed products, telemetry, session plans and three generations of
  machine-readable format. The owner has already designed the cure, the
  district model in `standards-map.toml` (0-canon, 1-formats, 2-protocols,
  3-practice, 4-readiness, 5-machine, 6-telemetry, 9-archive, onramp,
  root), and executed the first two moves (0-canon extraction, 9-archive
  move). What remains is executing the rest of that map and removing what
  the map itself marks deprecated.
* The design document the map cites (`03-STANDARDS-REORG.md`) is not in
  any repository and is presumed lost with the workstation. The `target`
  column of `standards-map.toml` is the surviving record of the design;
  this pack re-states it so it cannot be lost twice.
* Root clutter: 62 visible entries plus 11 dot entries. The target is
  about 28 visible. The map already names a target for every entry; the
  plan sequences the moves so each PR is one mechanical packet with a
  mechanical acceptance test.
* Retired formats are still load-bearing: 222 `.a2ml` files, of which
  the Must gate, the Debt ledger, the Hypatia rules, the DYADT claims
  file and the canon criteria are live inputs. The canon has no
  `standards_chora.deed`, so it fails its own D312 rule.
* Issues: 220 open. 63 can be closed or merged today with a pointer
  comment (29 done, 9 moot, 6 superseded, 19 duplicates). 69 are small
  in-repo fixes a Sonnet-class model can do. 48 are estate campaigns
  where standards owns the policy and the file changes land elsewhere.
  24 need one owner answer each. 16 are blocked on credentials or
  rulings. Every record, with the literal, golden and mischief reading,
  is in the appendices.
* CI: 59 workflows, 23 self-gates, 15 reusables, 6 dead. Only three
  checks are live-required on `main` and all three are admin-bypassable;
  the 20-check gate ruleset has been disabled since 2026-10-05, and a
  Dependabot PR was merged through red on 2026-10-13. Two reds on main
  are this repo's bugs and are fixed in this PR.
* Wiring: no phantom pins, but 40 drifts across the seven siblings, six
  of them high. Siblings copy policy text instead of pinning it; hypatia
  carries a stale licence register; six of seven build the Hypatia
  scanner from a floating ref.

== Method

Each issue was read in full (body and every comment) and then tested
three ways, as the owner asked:

Literal:: What the text asks for, as written.
Golden:: Whether the literal reading now produces an absurd or
  contradictory result against the current facts (A2ML retired, the
  spec registry retired, Python banned, Deno permitted at tier 2 since
  #1249, the RSR tree archived,
  the workstation wiped). Where it does, the sensible reading is stated.
Mischief:: What defect the issue was filed to remedy, and whether that
  defect still exists in the tree. This is checked, not inferred: the
  record cites the file, commit or run that proves it.

The rulings on #787 (D1 to D331) and #1234 (D332 onward) were compiled
into a ledger (<<appendices>>) and applied before any disposition was
written, so nothing already ruled is re-asked. 317 of 334 ids have
text; 17 were never posted and two (D297, D315) are declared lost.

Measurements: `git ls-files` counts, `scripts/check-standards-map.sh`
(Gate D), `scripts/check-canon-lockstep.sh` (Gate A),
`scripts/run-mustfile.sh`, `scripts/run-debtfile.sh`,
`scripts/link-rot-guard.sh`, the Actions API for every workflow, and
grep over the seven sibling checkouts. The local toolchain lacked Go
`yq`, `nickel`, `shellcheck`, `actionlint` and `just`, so 16 of 81
shell test files fail locally for want of tools while Self Test is
green on `main`; CI is the oracle for those.

== Issues: 220 dispositions

The eight dispositions used, and what each means for a bot:

[cols="1,3",options="header"]
|===
| Disposition | Meaning

| CLOSE-DONE | The defect is gone; a fixing PR or commit exists. Close with a pointer comment naming it (Intake Rule 7).
| CLOSE-MOOT | The premise no longer holds (wiped workstation, archived tree, banned tool). Close citing D110.
| CLOSE-SUPERSEDED(#N) | Another issue or ruling carries the work. Close naming it.
| MERGE-INTO(#N) | A duplicate. Copy any orphaned evidence into #N first, then close.
| OWNER-RULING | One yes/no question for the owner; the exact question is in the record. Goes on the decision sheet.
| BOT-DO | A small fix inside this repository, with files, steps and acceptance named in the record.
| ESTATE-CAMPAIGN | Standards owns the policy; the file changes land in other repositories, one PR per repo, never admin-merged.
| KEEP-OPEN-BLOCKED | Blocked on a credential, a ruling, or another issue, named in the record.
|===

[[placement-rules]]
=== Placement rules (the test a bot applies to any file)

. Does GitHub, git, a scanner or the spine's `root-allow.txt` read it at
  the root? Then it stays at the root. Otherwise it leaves the root.
. Is it a *constitutional or canon-law* text, or a canon.lock artefact?
  `0-canon/`.
. Does it define *what we read and write* (a grammar, a format spec, a
  mapping spec, a conformance corpus, the reference tooling for that
  format)? `1-formats/`.
. Does it define *how systems or agents talk* (a protocol spec, its
  schemas, IETF drafts, its reference generator)? `2-protocols/`.
  Implementations, websites, DNS, containers and language bindings do
  not: they go to the protocol's own repository or to `9-archive/`.
. Does it tell people or agents *how to work* (a policy, a standard of
  practice, a runbook, a training text, an authoring standard)?
  `3-practice/`.
. Does it *grade maturity*? `4-readiness/`.
. Does it *enforce or index* (scripts, tests, gate config, rule
  definitions, tooling, templates that a reusable workflow reads)?
  `5-machine/`.
. Is it *measured, dated and about the estate as it is* (boards,
  audits, affirmations, ledgers, per-repo requirement data)?
  `6-telemetry/`.
. Is it *history*: a retired format, a superseded plan, a frozen
  snapshot, a last copy? `9-archive/`. Nothing there is edited to
  satisfy a gate.
. Is it an ADR, the wiki, or onboarding (quickstarts, warm-ups)?
  `docs/`. Nothing else lives in `docs/`.
. A `README.adoc` sits at every district root and routes; the root
  README routes to the districts and nothing deeper.

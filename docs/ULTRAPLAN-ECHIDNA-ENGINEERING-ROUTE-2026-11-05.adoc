[[verdict]]
== Verdict in one page

*Where ECHIDNA stands.* The facts below come from a 12-agent system map of
`hyperpolymath/echidna` at `6dbfea5`. They are reported to the owner
unchanged, and three of them were re-checked at `0211aa0` (2026-11-05).

* The public API (`api.nesy-prover.dev`) executes provers on caller input
  with *no authentication*. It runs `:latest` with `AutoUpdate=registry`,
  so every release auto-deploys
  (`deploy/hetzner/echidna.container`, `deploy/hetzner/Caddyfile`;
  re-checked). Contained by echidna#461 (W0 stopgap) once applied on the
  host.
* Solver integrity checking fails *open*. A `--sandbox` request is
  ignored. No certificate is ever produced, because `certificate_hash` is
  hard-coded to `None`. The CLI `verify` discards the typed outcome.
* The trust kernel (`src/rust/verification/confidence.rs`) has two latent
  defects. They are unreachable only because no certificate is ever
  verified, and both go live the moment certificates are threaded through.
  Re-checked:
** Level5 is granted when the _primary_ prover is small-kernel, without
   checking that the confirmers are (line 95).
** Level4 is admitted on `certificate_verified` without `has_certificate`.
* The formal artefacts are parallel models of the code, not bindings to it.
  Several theorems are vacuous or stale.
* The 14 `allow-fail` CI units expire on *2026-11-30*. After that date,
  every PR that touches a workflow fails (re-checked: 14 occurrences in
  `.github/`).
* Cap'n Proto IPC is stubbed, and no trained model weights exist.
  echidnabot is vendored into gitbot-fleet as a full product, against the
  fleet's thin-adapter rule.

*What to build, in one sentence.* Contain first, then make one canonical
Idris2 trust-kernel spec the single source the Rust kernel, the proofs and
the tests are all generated from or checked against. Then cage every
subprocess, make certificates real, raise the epistemic level from `belief`
to `epi` to `sound` only on evidence, and let learned advice reorder
candidates but never decide a verdict.

*Size.* 13 waves (W0, W1a/b, W2a/b, W3a/b, W4a/b, W5–W8), about 450
agent-days and 68 owner rulings. At 10–16 concurrent agents, and with
rulings returned within two working days, that is about 67 working days.
This environment's guideline is fewer than 10 agents per workflow, so the
waves run as sequenced phases. The milestones below assume the higher
concurrency:

* containment complete: about day 13;
* first `epi`: about day 39;
* gated model promotion: about day 50;
* first `sound`: about day 60, unless the pacing ruling (#20) holds it.

[[how-made]]
== How this plan was made

Four planners wrote independent routes from the same system map:

* *A*, trust kernel first;
* *B*, proofs bind the code;
* *C*, one vertical slice, then widen;
* *D*, the neurosymbolic loop.

Three judges scored every route, one per lens: elegance and correctness,
dependability and security, and executability in an ultracode session. A
critic then attacked the synthesis, and the synthesis was revised. All 95
dependency edges were checked by script.

|===
|Route |Elegance and correctness |Dependability and security |Execution |Total

|A — trust kernel first |8 |7.5 |7.5 |*23*
|B — proofs bind the code |*8.5* |6.5 |6 |21
|D — neurosymbolic loop |7 |5 |*8* |20
|C — one vertical slice |6.5 |7 |6 |19.5

NOTE: The workflow's own tally listed B first at 21. Routes A and D each
appeared under two spellings of their names, so their scores were split.
The totals above are merged from the per-lens judgements. The synthesis
had already caught this.

*The synthesis* keeps Route A's order (containment, then one pipeline,
then the cage and certificates, then outward work). It takes Route B's
architecture whole: one spec feeds an oracle, the oracle emits committed
JCS golden tables, and exhaustive tests, Kani and cargo-mutants bind the
shipped Rust to those tables. It grafts on:

* from Route C, the single `ci-gate` aggregator;
* from Route D, the outcome observer, `echidna.attempt/1`, the writer
  allowlist, the identity-keyed split and the promotion gate.

*Edge check, re-run independently.* The script and data are committed in link:ULTRAPLAN-ECHIDNA-ENGINEERING-ROUTE-2026-11-05/README.adoc[the companion directory]:

* 87 of the 95 edges are strictly ordered by wave.
* 2 are same-lane stacks inside one wave (CI-3→CI-4, A-4→A-5).
* 6 hold at the level of their declared parts (L-15a→L-5, A-5→A-6,
  A-6→B-1, PB-4→PB-5, PB-4→PB-6, PB-6→PB-5). Each part's wave was
  checked.
* One of the six is a same-wave cross-repo stack: A-6b→B-1c in W7.

[[ruling-32]]
=== What the Epi-gated ruling changes

The synthesis was written for the recommended arm (Level3). Under the
ruled arm, *only confirmers at `Epi` or above count toward cross-check
trust levels*. A cross-checked result whose confirmers are only `Belief`
cannot exceed Level2. This makes "Level3 + Belief" unrepresentable inside
the mechanism scale itself.

Consequences, which override the corresponding text in the generated
sections below:

* *W2a spec block.* `TrustKernel.idr` takes the confirmers' epistemic
  level as a typed input. The cells that change are the Level3–Level5
  cross-check cells. Each cites ruling #32 and is diffed against the W0
  characterisation golden.
* *Visible downgrade.* From W2a until A-6a lands (W4a, the first `epi` in
  the contract), every cross-checked result that consumers see reports
  Level2. This is honest, not a regression.
** CHANGELOG and STATUS say so in the same PR.
** echidnabot (B-4, W2b) renders the level it receives. It does not
   reconstruct an older one.
* *No `legacy_level` field.* The synthesis's elegance judge priced this arm
  with a temporary `legacy_level` field. This plan does not add one.
** Consumers get the honest level.
** The W0 characterisation golden preserves the old table for anyone who
   needs to compare.
** Adding a field only to remove it later is the churn the elegance lens
   penalises.
* *A-10, the combined grade (W4b).* Its cap rule ("Level≥4 implies ≥Epi")
  becomes a theorem of the spec, not a separate rule. A-10 still adds the
  combined grade as a new output, and Kani checks the theorem.
* *Level5* requires at least two distinct small-kernel confirmers, each
  with a verified certificate and each at `Epi` or above. This fixes the
  defect at line 95.
* *Typed factors* make `certificate_verified` without `has_certificate`
  unrepresentable. This fixes the second defect.

[[data-flow]]
=== How a proof obligation flows

1. **Origin.** An obligation starts in one of three ways:
- panic-attack pairs a finding with an author-supplied SMT-LIB sidecar (`@covers safe:rule-id:…`). `panic-attack obligations --emit` turns this into a JCS obligation with a UUIDv8 content id over the JCS-normalised goal.
- An echidnabot webhook check runs on a PR.
- Someone calls `echidna verify --output json` or POST /api/verify directly.

2. **Queue.** echidnabot accepts the obligation through the authenticated /graphql submitProofObligation mutation (B-7) and stores it as PENDING. The B-5 dispatcher drains the queue and calls ECHIDNA REST /api/verify with its bearer token (P0-5). Caddy only lets authenticated requests reach execution routes (P0-6).

3. **Server.** server/auth.rs checks the token. The route resolves the ProverKind through the single echidna-core enum (V-9) and calls verify_with_trust(state, policy) (V-5), which records the policy name.

4. **Advice (optional; may only reorder).** The GNN, reached through gnn_api_url (L-1) over Cap'n Proto on a UDS with HTTP fallback (I-2/I-3), and VeriSimAdvisor (L-10) may reorder candidate premises, tactics or provers. They cannot set an outcome, and the non-interference test checks this.

5. **Integrity.** The solver binary is resolved in-process and checked against the owner-signed manifest (SHAKE256-512 and BLAKE3). Any status other than Verified is an error unless an opt-in is recorded (P0-1, P0-2, V-10). The result is written to provenance.integrity.

6. **Execution.** ProverProcess runs the binary under bwrap or podman, denies unsandboxed execution by default, and enforces a timeout and an output cap (V-7). The backend's check() returns a typed ProverOutcome, in which an environment failure becomes Error (V-2, missing-binary-is-error). The sandbox mode is written to provenance.

7. **Axioms.** AxiomTracker classifies the axioms the proof uses. A Reject classification caps the result.

8. **Certificates.** If the policy requires one, the backend emits Alethe or DRAT/LRAT. carcara or drat-trim checks it, running through ProverProcess and listed in the integrity manifest. The result is a typed CertificateStatus plus certificate_hash (V-8).

9. **Trust.** The spec-bound kernel computes TrustLevel 1–5 from the typed factors (F-1, trust-factors-typed). A coprocessor-derived step adds a cap factor (I-8).

10. **Arbitration.** If cross-check was requested (V-11), the arbiter runs. Portfolio is the default. Discounted Dempster-Shafer, grouped by standpoint, applies only among sources that do not certify (A-7, A-8).
- Consequence probes yield DeclaredCorrespondence with a standpoint record, which gives `epi` (A-3, A-6a).
- A kernel-replayed OpenTheory article whose α-normalised term_hash matches yields KernelTranslation, which gives `sound` (A-4, A-5, A-6b).

11. **Combined grade.** The cap rule applies: Level≥4 requires Epi or better (A-10).

12. **Emit.** prove.result/1 is emitted together with the provenance envelope: integrity, sandbox, policy, certificate, arbitration, level and grade.

13. **Record.** OutcomeObserver writes one echidna.attempt/1 row (ids minted by ids.rs) to VeriSim, with advice provenance, identity key, scheme and identity_complete. Rows with status=error, and rows from backends outside the allowlist, are marked excluded_from_training. MetaController.record_outcome is a second observer on the same event (L-11). In production this needs L-9, which in turn needs the host P0-6 evidence and ruling #46. In CI the same observer writes to the pinned ephemeral VeriSim.

14. **echidnabot.** echidnabot posts a check-run with outcome, receipt, level and grade (B-1a/B-1b/B-1c). In regulator mode it blocks merges. It marks the obligation terminal and publishes it to shared-context, so the fleet report-back writes a real verdict (B-2, B-3).

15. **panic-attack.** The aggregate ingests prove.result/1, re-hashes it with BLAKE3, and marks the finding Backed (verified), Contradicted (refuted) or Unverified (error, timeout or unknown).

16. **proof-burrower.** The ledger records the receipt. On every read it re-derives result_id with ids::content_id and demotes the entry to a warrant on mismatch (PB-1).

17. **Retrain.** On a schedule (L-13, enabled only when L-9 is live), retrain reads a time window from production VeriSim (L-7), builds outcome-labelled features (L-8), trains on the identity-keyed train split, and evaluates on the held-out split against a measured cosine baseline. The promotion gate then either promotes the model or records a rejection in the registry. /reload accepts only a registry id. Every eval row names the store it read from.

18. **Status.** STATUS and the claims register are regenerated from code, from the registry, and from the DEFERRED list kept by the gates. The dogfood gate later runs ECHIDNA's own proofs through this same path and records their receipt ids.

=== Theory ladder (what has to be decided or proved, and when)

* Θ1 (R0/R1, before W1a). Typed verdict algebra: {Proved, Refuted, Timeout, Error, Unknown}. Error and Unknown count as absent evidence, never as negative evidence. Settles D-B, V-2/V-3, how environment failure enters fusion, and that error rows are never used as training labels.

Later inputs (the coprocessor cap) and outputs (the combined grade) extend it without changing existing cells. Settles:
** Level2 vs Level3. Recommended: Level3. Labelled most elegant: only confirmers at Epi or above count. *Ruled 2026-11-05: the Epi-gated arm (see <<ruling-32>>).*
** Level5: requires at least two distinct small-kernel certified confirmers.
** portfolio_confidence.
** Stage 8c claims.
* Θ4 (W2a). Stage order as data. PIPELINE is exported, and the ordering theorems quantify over it. Settles 'reorder vs rewrite', and makes ordering drift impossible.
* Θ5 (before W3a). A certificate short-circuits fusion: it is a witness, not a weight. Numeric fusion applies only among non-certifying sources.
* Θ6 (before W3a; echo-types is cite-only). Identity as equivalence in the Echo-fibre reading:
** belief = a shared fibre under a lossy invariant.
** epi = equal consequence partitions under standpoint-independent probes.
** sound = a kernel-checked witness.
** completeness = injectivity on the fragment.
Settles the identity_complete join semantics, the cluster as the unit of the held-out split, and the A-5 acceptance criterion.
* Θ7 (before W3a). Standpoint independence: sources are partitioned by kernel, library, encoding and authorship, and epi needs at least two classes. Z3 and CVC5 over the same encoding count as one standpoint until A-3 shows otherwise.
* Θ8 (after A-3 data, W4a). Dependence-aware numeric evidence: discounted Dempster-Shafer grouped by standpoint, with the cautious rule inside each group. The alternative is Bayesian fusion with learned likelihoods and one vote per group.
* Θ9 (before W4b). Combined grade: a product order with a cap rule, Level≥4 implies ≥Epi. Settles the single user-facing verdict and the regulator-mode thresholds.
* Θ10 (before W3a). Lexicographic Pareto: epistemic level first, then latency, axiom cost and certificate size. Soundness is never traded for speed, and hypervolume is at most an additive field.
* Θ11 (before W2b). Receipts are content-addressed warrants, and receipts are transitive: a consumer may keep or lower a grade, never raise it, and every hop re-derives the id. Content ids are UUIDv8 over JCS bytes. Record ids follow the ruled ADR-008 scheme, and parsers accept every version ever minted. Settles the ledger's no-laundering rule, the LedgerBackend semantics, and the panic-attack aggregate verdict.
* Θ12 (before W3a). Learning as off-policy evaluation over logged advice. Promotion is decided only by the identity-keyed held-out evaluation, and every evaluation names its data store. Routing stays deterministic: no exploration budget unless the owner rules for one.
* Θ13 (before W3a). Proof search as an MDP over proofstate/1, with reward ordered closure > goal reduction > cost. Settles the PB-6 fitness function, the Stage 3c rows, and whether the value head is learnable or stays a research item.
* Θ14 (before W1b; restated in W6). Parallel search as refinement: Chapel proposes, Rust disposes. The coprocessor tier is a cap, never a raise. Turning parallel search on by default is a performance decision only.
* Θ15 (stated in W2b, proved in W8). Non-interference for advisors: acceptance factors through verify_j of the same statement, and advisor outputs are typed as orderings only.

[[session]]
== The ultracode session, wave by wave

**Conventions, set in W0 and used by every later wave:**
- (a) **Gate convention.** Every check is PASS, FAIL or DEFERRED(reason), and DEFERRED is allowed only for a named ruling, secret, hardware item, owner host action or cross-repo push denial. A DEFERRED check is appended to the next wave's gate script, its item moves with it, and STATUS lists it.
- (b) **Where gates run.** Each wave's gate runs on the integration ref `wave/WN`: the main agent's worktree stacks the wave's verified PRs, and the gate is run there. That makes the wave agent-complete. The gate runs again on main after the owner merges, which makes the wave landed. The next wave branches from `wave/WN`. If two waves are agent-complete but not landed, the session pauses for owner merges.
- (c) **Integrator.** Each repository has one integrator lane per wave. It owns Cargo.toml/Cargo.lock, the lib.rs files, the module-registration files, workflows and ci-gate.kyaml.
- (d) **Rulings role.** The rulings role (the main agent) is the only editor of the rulings-ledger ADR.

**Phase α (serial).** Merge CI-1 (#458, with actions.lock relocked by the standards script) and CI-2. Run experiment E0, the push-access probe through add_repo with access=push for echidnabot, gitbot-fleet, proof-burrower, panic-attack and verisimdb.

**Phase γ (verification).** Two adversarial verifiers.
- The first runs `just ci-local` on a clean checkout, opens a no-op probe PR, and runs the expiry check with FAKE_DATE=2026-12-01.
- The second diffs the hotspot goldens and tries to sneak a bad fixture past CI-11.
Failures go back to the owning lane.

== Risks and their mitigations

* The W2a kernel change alters levels that consumers can see (Level5 tightening, typed factors). Mitigation: diff against the W0 characterisation golden, cite a ruled ADR anchor for every changed cell, add a CHANGELOG entry, and re-point echidnabot (B-4) in the following wave as part of the same spec block.
* Fail-closed integrity and the default-deny sandbox could turn every CI job red at once. Mitigation: each lands with a recorded opt-in that shows up in provenance, CI sets that opt-in explicitly, `integrity init` lands in W1b, and bubblewrap is installed in the prover lanes.
* Ubuntu 24.04 hosted runners restrict unprivileged user namespaces through AppArmor, so bwrap may fail there. Experiment E4 checks this before D-D. Podman is the fallback. The fault-injection case 'unavailable → error' stays valid either way.
* dispatch.rs is serialised through a single K lane. Mitigation: keep each PR small, put all new logic in new modules, and have K only thread calls through.
* The integrator lane can become a bottleneck, because every scaffold, registration and ci-gate edit goes through it. Mitigation: scaffolds land at wave start in one PR, lanes hand job bodies over as scripts, and promotion is batched at wave end.
* Owner-merge throughput. About 13 waves of small stacked PRs need human review, and the session pauses at two unmerged waves. Mitigation: wave-level PR indexes, a verifier summary per PR, and a gate-pass record on the integration ref.
* Owner-ruling latency: 68 rulings, nine batches. Mitigation: ask one wave ahead, DEFERRED checks with explicit carry-forward, flagged drafts, and lanes that need no ruling kept busy. CI-4 is the one hard deadline, and it is scheduled in W0.
* Production loop slip. If the host P0-6 evidence or ruling #46 is late, L-9, L-10 and L-13 are all DEFERRED. The loop is then demonstrated only in CI, and STATUS must say so. No stand-in is presented as production.
* The hotspot split could collide with open PRs #455 and #458. Mitigation: those land first, the split is byte-identical and golden-gated, and the other W0 Rust lanes only add new test files.
* Proof toolchains are missing from agent containers, and the Lean status is contradictory. Mitigation: commit JCS goldens, use pinned CI images, run experiment E2, and run NEW:lean-build-reconcile in W0.
* Flakes in ci-gate create pressure to bypass it. Mitigation: a shadow run first, small fixture sets with the full suites nightly, and a narrow fault-injection gate kept separate.
* Contract churn could break consumers. Mitigation: one envelope, conformance tests in four repos before D-B lands, and /2 only if a field has to change meaning. The UUID migration is read-compatible: parsers accept v7 and v8.
* The learning loop could be poisoned or leak test data. Mitigation: the writer allowlist, exclusion of error rows, and a cluster split with a zero-shared check. Residual risk: false negatives in dk-shape-v2, so its collision statistics are published with every eval.

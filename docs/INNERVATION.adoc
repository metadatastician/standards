= Standards Innervation Architecture
:version: 0.1.0
:status: Draft
:updated: 2026-04-05

== What this is

The standards repo is moving from a static 6a2 file-per-repo model to an
innervation architecture — standards that *run through* the code rather
than sit beside it.

The old model stored metadata in six A2ML files per repo
(STATE/META/ECOSYSTEM/AGENTIC/NEUROSYM/PLAYBOOK). Scaled to 290+ repos,
that became ~1800 files that drift out of sync, can't enforce, can't
derive, can't visualise.

The new model runs standards through five layers that already exist.

== The five layers

[cols="1,2,3",options="header"]
|===
| # | Layer | Purpose

| 1 | Git                  | Code, specs, authored decisions (unchanged)
| 2 | `coordination.k9`    | Per-repo nerve receptor — invariants, afferent/efferent signals, reflex guards
| 3 | `STATE.a2ml v2`      | Thin session journal (phase + blockers + last action)
| 4 | VeriSimDB            | Central knowledge graph (octads for CRG, proofs, compliance, ecosystem links, annotations)
| 5 | Hypatia              | Enforcement layer (scans, rules, recipes)
|===

**PanLL** sits on top as the visibility lens. **Groove** is the nervous
system signalling medium. **ECHIDNA** verifies proofs at gates.

Per-repo footprint shrinks from 6–7 files to 2 (`coordination.k9` +
`STATE.a2ml v2`).

|===

== Walk-through (machine-readable)

A commit lands in repo X → Groove emits `commit.pushed`. Subscribers:

1. **inline-annotations extractor** runs → emits `annotation.extracted` for
   each `@trust`/`@contract`/`@grade` found → VeriSimDB stores
   `inline-annotation` octads.
2. **Hypatia** runs → emits `compliance.finding.new` for each violation →
   VeriSimDB stores `compliance-scan` octads → `hypatia.finding` fires back
   to repo X's efferent loop.
3. **ECHIDNA** (if proofs changed) re-verifies → emits `proof.verified` →
   VeriSimDB stores `proof-status` octads.
4. **CRG rule** derives a grade from the accumulated evidence → emits
   `crg.grade.changed` if it moved.
5. **PanLL panels** refresh from VeriSimDB and render the new state.

All signals are listed in `2-protocols/groove/spec/INNERVATION-SIGNALS.adoc`.

== For humans

- Start with this document
- Then read `coordination.k9` in this repo — it is both the spec for the
  format and the reference instance
- Then browse `1-formats/sub-specs/inline-annotations/examples/sources.md` to see the
  annotation grammar in 8 languages
- To initialise `coordination.k9` in a new repo: run
  `k9-init /path/to/repo`
- To convert a PLAYBOOK runbook to Hypatia recipes: run
  `playbook-to-recipe --playbook PATH --out DIR`

== Roll-out

The standards repo is the pilot. Migration to other repos proceeds by
natural diffusion:

1. High-traffic repos that currently own 6a2 files get migrated first
   (run `k9-init`, write invariants, deploy VeriSimDB ingest for that repo)
2. New repos use `coordination.k9` + `STATE.a2ml v2` from scaffolding
3. Low-traffic repos are migrated opportunistically on next visit

There is no forced migration. 6a2 files continue to work until their repo
is migrated.

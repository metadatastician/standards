= Trusted-Base Reduction Policy
:revdate: 2026-05-27
:status: ADOPTED
:audit: hyperpolymath/standards#195
:audit-licence: hyperpolymath/standards#196
:audit-docs: hyperpolymath/standards#197
:enforcement: hyperpolymath/standards#211
:precedent: hyperpolymath/boj-server backend-assurance harness

This document is the canonical estate-wide policy for managing
*soundness-relevant escape hatches* in proof-bearing code — the
unconditional, unproven primitives that every formal-methods toolchain
provides for ergonomic or extraction-boundary reasons:

[cols="1,1,3", options="header"]
|===
| Language | Tier | Escape hatches in scope

| Coq      | core     | `Axiom`, `Admitted`, `admit.`
| Coq      | extended | `Parameter(s)`, `Conjecture(s)`, the `admit` and `give_up` tactics
| Lean     | core     | `axiom`, `sorry`
| Lean     | extended | `@[implemented_by]`, `@[extern]`, `native_decide`, `Lean.trustCompiler`, `Lean.ofReduceBool`, `admit`, `unsafe def`, `partial def`
| Agda     | core     | top-level `postulate`
| Agda     | extended | `{-# TERMINATING #-}`, `{-# NON_TERMINATING #-}`, `{-# NON_COVERING #-}`, `--type-in-type`, `--no-{termination,positivity,coverage,projection-likeness}-check`, `--allow-unsolved-metas`, `primTrustMe`, `{!!}`
| Idris2   | core     | `believe_me`, `really_believe_me`, `assert_total`, top-level `partial`, `%default partial`
| Idris2   | extended | `?hole` (unsolved goal)
| F\*      | core     | `assume val`, `admit_p`
| F\*      | extended | bare `assume`, `admit()`
| Dafny    | extended | `{:axiom}`
| Rust/Haskell | core | `unsafePerformIO`, `unsafeCoerce` (where used in soundness-relevant positions)
|===

*Tiers were introduced on 2026-10-30* (see § "Extended tier" below). A `core`
marker is enforced exactly as it has been since standards#211: undocumented is a
failure. An `extended` marker is *reported* and *budgeted*, never failed on
sight.

Two entries from the original table are gone, deliberately:

* **Lean `noncomputable`** — it is not in the detector and was not a soundness
  hole: it says "this definition has no code", which reduces the trusted
  computing base rather than enlarging the trusted base. Listing it here was a
  claim the tooling never made good on.
* **Cross-language `TODO PROOF` / `FIXME PROOF`** — the enforcement script has
  never grepped these, and should not: a TODO is a schedule, not a soundness
  hole, and grepping prose for "TODO" in 416 repositories measures the prose,
  not the proofs. `OWED:` is different and *is* honoured — as one of the
  inline discharge tokens (§ "Annotation conventions"), which is what it always
  was in the Idris2 form.

The 2026-05-26 estate proof-debt audit (link:{audit}[#195]) found these
markers spread across ~30 active repos, with concentrations of
`believe_me` at extraction boundaries (Rust↔Idris2 FFI, codec runtime)
and `partial` clusters that conflate "totality just hard to prove" with
"totality genuinely impossible". This policy gives every such marker a
canonical disposition path so the trusted base shrinks over time
instead of accreting.

== Three permissible dispositions

Every soundness-relevant escape hatch in the estate MUST be one of:

[cols="1,1,3", options="header"]
|===
| Disposition | Marker | Definition

| (a) DISCHARGED
| —
| A proof exists. The escape hatch has been deleted or replaced with a
proof term / total function / proven instance.

| (b) BUDGETED
| `// TRUSTED: <kind>; <budget>`
| The escape hatch is necessary at this layer (FFI boundary, foreign
extraction target, performance corner case). It is covered by
property-based or adversarial tests at a documented refutation budget
(e.g. "tested at N=10⁹ inputs across `cargo test --release --features fuzz`").
The budget is the load-bearing component — without it, "covered by
tests" is unfalsifiable.

| (c) NECESSARY AXIOM
| `-- AXIOM: <name>; <justification>`
| The escape hatch encodes a metatheoretic assumption that cannot be
discharged within the working logic (e.g. function extensionality,
propositional truncation, classical choice, certain decision procedures).
It is enumerated in `docs/proof-debt.md` with a one-paragraph
justification and a citation pointing to the canonical formalisation
elsewhere (echo-types, MathLib4, agda-stdlib, etc.).
|===

A marker that is *none of (a)/(b)/(c)* is **debt**, and must appear in
the repo's `docs/proof-debt.md` with a deadline (or "INDEFINITE" with a
reason) and an owner.

== `docs/proof-debt.md` schema

Every proof-bearing repo MUST maintain a `docs/proof-debt.md` (or `.adoc`)
with the following structure:

[source,markdown]
----
# Proof debt

## (a) Discharged in this repo
- (none — entries removed when proof lands)

## (b) Budgeted — tested with refutation budget
- `path/to/file.rs:LINE` — `unsafe_extract_bytes`
  - **Kind**: extraction boundary (Rust→Idris2 ABI)
  - **Test**: `cargo test --release --features fuzz extract_bytes_qc`
  - **Budget**: 10⁹ inputs / N=10000 shrinks
  - **Last run**: 2026-05-26 (CI run #12345 — green)

## (c) Necessary axiom
- `formal/Foo.v:LINE` — `axiom funExt`
  - **Justification**: function extensionality; not derivable in
    constructive Coq without UIP. Standard practice; see Mathlib4
    `Mathlib.Logic.Function.Basic`.
  - **Citation**: Univalent Foundations §2.9; Mathlib4 commit abc1234.

## (d) DEBT — actively to be closed
- `formal/Bar.v:LINE` — `Admitted` `preservation_lemma`
  - **Owner**: @maintainer
  - **Plan**: discharge by induction on typing-derivation; subgoals
    (1)-(7); blocked on (4) which needs the substitution lemma.
  - **Deadline**: 2026-08-01 / "INDEFINITE: dependent on echo-types
    Lift ⊤ rung-C settlement".
----

Disposition (d) is the only category that should *shrink* over time.
(a) shrinks too, but only by promotion through proof; (b) and (c) are
load-bearing and should stay stable.

== Annotation conventions in source

Mark every escape hatch inline so the disposition is local to the code:

[source,rust]
----
// TRUSTED: extraction-boundary; tested via `cargo test fuzz` (10⁹ inputs).
//   See docs/proof-debt.md §(b) entry "unsafe_extract_bytes".
unsafe fn unsafe_extract_bytes(...) -> ... { ... }
----

[source,idris]
----
-- TRUSTED: extraction-boundary; tested via `idris2 --test` (Hedgehog, N=10⁶).
--   See docs/proof-debt.md §(b) entry "wasm_marshal_u64".
wasm_marshal_u64 : Bits64 -> ByteArray
wasm_marshal_u64 x = believe_me ...
----

For Idris2 *axioms* (disposition (c)), prefer the canonical form: a
doc-comment header (`|||`) starting with `OWED:` and a `0`-multiplicity
(erased) declaration. The erased multiplicity makes the term proof-only —
it cannot escape into runtime code and disappears from compiled output —
so the unproven assumption is structurally scoped to type-level reasoning:

[source,idris]
----
||| OWED: function extensionality at the typed-wasm export interface.
||| Necessary; not derivable in Idris2 0.8.0 without UIP.
||| See docs/proof-debt.md §(c) entry "funExtTW".
||| Citation: echo-types `Echo.FunExt`, Mathlib4 `Function.funext_iff`.
0 funExtTW : (f, g : a -> b) -> ((x : a) -> f x = g x) -> f = g
----

The `OWED:` token is recognised by `scripts/check-trusted-base.sh`
alongside `TRUSTED:` and `AXIOM:`. Use `OWED:` for proof-only erased
declarations (Idris2 0-multiplicity, Coq `Axiom`-of-Prop, Lean `axiom` in
`Prop`) and `TRUSTED:` for run-time soundness breaks (`believe_me`,
`unsafePerformIO`, `unsafe`).

[source,lean]
----
-- AXIOM: function extensionality; necessary; see docs/proof-debt.md §(c).
--   Citation: Mathlib4 `Function.funext_iff` (commit abc1234).
axiom funExt {α β : Type} (f g : α → β) :
  (∀ x, f x = g x) → f = g

-- For debt-style markers (disposition (d)), prefer the named sorry:
-- DEBT: substitution preservation; owner @maintainer; deadline 2026-08-01.
--   See docs/proof-debt.md §(d) entry "subst_preservation".
theorem subst_preservation : ∀ {Γ τ e e'}, Subst e e' → Typed Γ e τ → Typed Γ e' τ :=
  sorry
----

[source,coq]
----
(* AXIOM: function extensionality.
   Necessary; see docs/proof-debt.md §(c) entry "funExt".
   Cited from echo-types. *)
Axiom funExt : forall (A B : Type) (f g : A -> B),
  (forall x, f x = g x) -> f = g.
----

[source,agda]
----
-- AXIOM: propositional truncation; necessary; see proof-debt.md §(c).
postulate
  ∥_∥ : Set → Set
----

The leading-comment marker is itself part of the contract — the audit script in
section "Enforcement" below greps for it. Choose the marker by run-time vs
proof-time scope:

* `TRUSTED:` — run-time soundness break (`believe_me`, `unsafe`,
  `unsafePerformIO`, `assume val`, `:axiom`). Pair with disposition (b)
  BUDGETED and a property-test budget.
* `AXIOM:` — top-level named axiom (Coq `Axiom`, Lean `axiom`, Agda
  `postulate`). Pair with disposition (c) NECESSARY AXIOM and a
  citation.
* `OWED:` — Idris2-style erased (`0`-multiplicity) axiom or any
  cross-language self-documented debt marker. Pair with either (c)
  NECESSARY AXIOM (with citation) or (d) DEBT (with deadline and
  owner).
* `JUSTIFIED:` — a written argument accepted in place of a proof (2026-10-30).
  This is the correct token for the *defensible* extended-tier cases, of which
  `{-# TERMINATING #-}` beside a termination argument is the canonical one: the
  pragma is the author asserting termination where the checker cannot see it,
  and the argument is the evidence. Without a token that says "argued, not
  proved", the only options were `AXIOM:` (false — it is not a metatheoretic
  axiom) or silence (and then the marker reads as naked debt).
* `DEBT:` — known, owned and dated, pointing at a §(d) entry.

A note on history: `OWED:` was documented as recognised by
`scripts/check-trusted-base.sh` from the day this policy landed, but the script
only ever grepped `TRUSTED:` and `AXIOM:`. Every `||| OWED:`-annotated Idris2
assumption — 280 of them in `hyperpolymath/proven` alone — therefore read as
naked debt. The script now honours `OWED:`, `JUSTIFIED:` and `DEBT:`. That is
the repair of a false finding, not a relaxation of a gate.

== Extended tier: widening detection without red-boarding the estate (2026-10-30)

The original gate recognised one class of marker per language. A development can
be *postulate-free and still unsound*: an Agda `{-# TERMINATING #-}` waives the
termination checker, `--type-in-type` makes the logic inconsistent outright, a
Lean `@[implemented_by]` swaps a proved definition for an unverified one at
runtime, a Coq `Parameter` is an `Axiom` under another name. Any one of them
destroys the meaning of "proved". So detection was widened.

=== Why the new markers are not hard failures

The estate's proof-bearing repositories are not homogeneous, and the same token
is a defect in one and a defensible choice in another:

* `{-# TERMINATING #-}` beside a written termination argument is the pragma
  being used as designed;
* a `{!!}` goal in a work-in-progress module is a TODO, not a lie;
* `postulate` in a teaching example is the point of the example.

If the widening had landed as fail-on-sight across ~416 repositories, the
cheapest way for a red repository to get green would have been an entry in
`.trusted-base-ignore` — which suppresses the finding permanently and destroys
the signal the gate existed to create. A gate that costs one honest sentence
gets obeyed; a gate that costs an afternoon gets bypassed.

So markers are split into two tiers, and only the *new* ones are budgeted:

[cols="1,1,2,2",options="header"]
|===
| Tier | Undocumented marker | Exit | Rationale

| core
| fails
| 1
| Behaviour unchanged since standards#211. Every core marker here has been in
  scope for months; the estate has had its chance to document them.

| extended
| is reported; disposition depends on the mode
| 0 in `report`; 1 in `budget` only when the undocumented count EXCEEDS the
  declared budget; 1 in `strict` when any extended marker is undocumented. A
  repository inside its budget exits 0.
| New on 2026-10-30. A repository cannot be failed for a rule that did not
  exist yesterday.
|===

All three discharge routes apply identically to both tiers: an inline
`TRUSTED:` / `AXIOM:` / `OWED:` / `JUSTIFIED:` / `DEBT:` comment, an entry in
`docs/proof-debt.md`, or a path fragment in `.trusted-base-ignore`.

=== The three modes and the budget file

`.trusted-base-budget` in the repository root, optional:

[source]
----
# The number the survey measured, never a number that makes the board green.
mode: budget
extended-undocumented: 37
----

[cols="1,2,3",options="header"]
|===
| Mode | Fails when | Use

| `report` (default)
| never
| The state every repository is in on the day the widening lands. Findings are
  printed and annotated (`::warning file=…,line=…`), and the machine-readable
  `TRUSTED-BASE-SUMMARY` line carries the counts for the estate board.

| `budget`
| undocumented extended > declared budget
| After triage. The number is the count the maintainer accepts *after*
  classifying what is defensible, not the count the scanner produced.

| `strict`
| undocumented extended > 0
| Target state. Reachable once every extended marker is either discharged or
  annotated.
|===

Precedence: `--extended-mode=` / `$TRUSTED_BASE_EXTENDED_MODE` >
`.trusted-base-budget` > `report`. `--tier=core|extended|all` narrows the scan
(useful while triaging). A malformed budget file is exit 2 — a configuration
error must not read as a clean run.

The budget is a *ratchet*: it may decrease in any commit; raising it is a policy
change and needs a `Ratchet-exception:` line in the commit message, exactly as
`scripts/check-exemption-ratchet.sh` requires for the other ledgers.

⚠ *That ratchet does not yet cover this file.* `check-exemption-ratchet.sh`
compares ledger ENTRY COUNTS at the PR base and at HEAD; a budget is one integer
value, and `scripts/count-ledger-entries.sh` has no format that yields it. So
today a raised ceiling is a review obligation, not a mechanical one. Wiring it
is a known follow-up: teach the counter a `budget:` mode that prints
`extended-undocumented`, then add `.trusted-base-budget` to `LEDGERS`. Until
then, `mode: strict` is the only mechanically enforced setting — it needs no
base to compare against, which is exactly why the tiers are ordered this way.

=== Survey first, enforce second

`scripts/estate-trusted-base-survey.sh` measures the marker set across every
repository that calls the governance bundle and publishes a hit list, before
anything is enabled. Its constraints are the interesting part:

* GitHub's code-search API is scoped to the token. A fine-grained token granted
  one repository returns one repository, and its zero resembles a real zero.
  The script probes scope and *refuses to publish* a hit list it cannot stand
  behind.
* A code search is a proxy. Two runs on the same estate returned 914 and 1,184
  results for the same caller query, and any single query caps at 1,000. Both
  facts are printed next to the numbers rather than smoothed away; see
  `docs/CICD-SIGNAL-DISCIPLINE.adoc` § "Never report a proxy as a finding".
* Two markers cannot be expressed as a search at all (Agda `{!!}`, Idris2
  `?hole`). They are listed as `not-expressed` rather than omitted, because a
  hit list that hides what it could not see is worse than no hit list.

`--list-markers` on the check script prints the marker catalogue as TSV
(language, tier, id, description). It is the single source of truth the survey
and this document are checked against.

=== What the widening deliberately does not detect

Each of these would flag healthy code, and a gate that reds a healthy repository
is a gate that will be removed:

[cols="2,3",options="header"]
|===
| Not detected | Why

| Idris2 `%default total`
| It is the *strict* setting: it makes the totality checker mandatory. The hole
  is `%default partial`, which is detected. Flagging `%default total` would
  red-board every well-disciplined Idris2 repository, which is precisely the
  population most deserving of a green board.

| Coq `Hypothesis` / `Variable` / `Context` in a `Section`
| These are binders discharged at `Qed`, not axioms. Distinguishing a section
  binder from a file-scope axiom needs a parser; guessing "axiom" is wrong in
  the overwhelmingly common case. The file-scope spellings — `Parameter`,
  `Conjecture` — are detected, and `Print Assumptions` remains the authoritative
  check.

| Agda `{-# BUILTIN #-}`, `{-# COMPILE #-}`; Lean `@[simp]`, `noncomputable`
| They change compilation, not the trusted base.

| Prover *invocation* flags
| See below. There is no estate-wide "correct" way to invoke Agda, Lean or Coq.
|===

=== Why the prover invocation is not standardised

`JuliaPackageSpitter.jl` runs Agda under
`--safe --without-K --double-check --ignore-interfaces -W error` with a
builtin-only Prelude and no libraries, and gets a trusted base of four builtins
and zero postulates. That configuration is excellent *for a development that
imports nothing*. It is not a rule:

* `--no-libraries` requires a builtin-only Prelude. A repository using
  `agda-stdlib` cannot pass it, and would have to vendor or re-derive the
  standard library to comply.
* `--safe` interacts with the pragmas and flags now detected here; a repository
  mid-migration from `{-# TERMINATING #-}` may need it off for a release.
* The same applies to Lean (`--noBuild`? lake profiles), Coq (`-w`, `-q`) and
  Idris2 (`--check-total`): the flags that make one development strict make
  another unusable.

What *is* estate-wide is the disposition requirement: every escape hatch is
documented, and the count is visible. How a repository invokes its prover is
its own business, recorded in its own workflow — where its pin, its version
assertion and its negative controls live.

=== Rollout, and what a pinned caller sees

Reusable workflows are pinned **by SHA** in callers, so nothing here propagates
automatically. `governance-reusable.yml`'s `trusted-base` job checks the script
out at `job.workflow_sha` — the caller's pin — so a caller keeps the detector it
pinned until it bumps. The pin-bump list for this change, and the requirement
not to rename the job (the required context is derived from it), are published
in `docs/audits/2026-10-30-trusted-base-marker-widening.adoc`.

== Enforcement

Enforcement landed at link:{enforcement}[standards#211] as
`scripts/check-trusted-base.sh`, wired into `governance-reusable.yml`
as a `trusted-base` job. The script:

. Greps every soundness-relevant escape hatch in the caller repo, in two tiers
  (the catalogue is printed by `--list-markers`; the tables above are the
  normative list). Matching is comment- and string-aware per language: Coq
  nested `(* *)` with multiline strings, Lean nesting `/- -/` and `--`, and
  Haskell-style `{- -}` / `--` for Agda and Idris2 — with Agda `{-# … #-}`
  pragmas copied through verbatim, since those pragmas are themselves markers.
. Verifies each is one of:
.. preceded by a `TRUSTED:`, `AXIOM:`, `OWED:`, `JUSTIFIED:` or `DEBT:` leading
   comment (the comment block is walked back up to 15 lines), OR
.. enumerated by path in `docs/proof-debt.md` (or `.adoc`, or `PROOF-NEEDS.md`), OR
.. exempted via a path-fragment substring match in `.trusted-base-ignore`.
. Fails CI when a *core* marker is naked (no annotation, no proof-debt entry, no
  ignore-file exemption). Extended markers are reported, and their disposition
  follows `.trusted-base-budget` (§ "Extended tier").
. Emits `TRUSTED-BASE-SUMMARY tier=… core_total=… extended_undocumented=…` on
  every run that finds a marker, in every mode, so counts can be trended without
  parsing prose.
. No-ops cleanly on repos with zero proof-bearing files (true for most
  of the estate).

=== `.trusted-base-ignore` — path-fragment exemption file

For markers that should NOT need per-site documentation — typically
test fixtures that exist *to be detected* by the scanner, local
worktree shadows, or other intentional self-scan noise — the script
consults an optional `.trusted-base-ignore` file in the repo root.
Format mirrors `.hypatia-ignore`:

[source]
----
# Comments start with `#`.
# Each non-comment line is a path-fragment substring match against the
# repo-relative file path. Narrow the fragment to avoid hiding adjacent
# findings.

# Scanner test fixtures: exist solely to verify the detector fires.
test/soundness/fixtures/

# Local agent worktree shadows: not part of the canonical tree.
.claude/worktrees/
----

Prefer this over inline `TRUSTED:` comments only for *whole-path* or
*whole-directory* exemptions with a documented org-policy rationale.
Per-site `TRUSTED:` / `AXIOM:` comments remain the right tool for
one-off documented escapes where the rationale is local to a single
construct. `.trusted-base-ignore` is to `check-trusted-base.sh` what
`.hypatia-ignore` is to the hypatia scanner — same shape, same
discipline, separate scope.

A follow-up may extend it to fail CI when `docs/proof-debt.md` §(d) DEBT
entries are past their stated deadline.

This is the same shape as `check-licence-consistency.sh` (standards#201)
— local script, called from the governance bundle, no network
dependencies.

The seed `docs/proof-debt.md` for the `standards` repo itself landed at
standards#213 as the canonical example of the schema in action (15
markers triaged, 11 §(d) entries with named owners and discharge
recipes).

== Precedent: boj-server backend-assurance harness

The pattern this policy codifies is already deployed in
link:{precedent}[boj-server's backend-assurance harness] (memory:
`project_boj_server_backend_assurance_harness`):

* 5 class-J axioms identified as irreducible in Idris2 0.8.0 (cannot
  be discharged within the type theory).
* Each one is property-tested *and* extracted to Rust where the
  property runs against the real Idris2 RTS implementation, not a
  mocked one.
* The trusted base is documented in `docs/proof-debt.md` and shrinks
  one entry per PR over a ~3-month roadmap.

That harness is the reference implementation. New proof-bearing repos
adopting this policy should adapt it rather than reinvent it.

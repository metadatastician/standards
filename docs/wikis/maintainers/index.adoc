=== The merge decision layer is part of the standard

Branch protection is not infrastructure that someone remembers to configure; it
is the thing that decides whether any of the other guardrails can bite.

* *Check producibility before trusting a required check.* A required context
  that no pull request can publish blocks every pull request forever, and the
  only way through is a bypass that discards the rest. Run
  `scripts/check-required-contexts.sh` locally; it is also a PR gate and a
  weekly cron. (`docs/audits/audit-ci-context-producibility-2026-09-20.adoc`.)
* *Never add a standing bypass.* Bypass is all-or-nothing: using it once
  discards every required check in the ruleset. If the ruleset is blocking
  something that should land, fix the ruleset — the escape hatch is to disable
  it deliberately, which leaves an audit trail.
* *Edit protection with the narrow instrument.*
  `scripts/fix-required-context-name.sh` (report-only by default) repoints one
  named context in one named ruleset and refuses when the before-state is not
  what it expects. Do not hand-edit a ruleset payload with ad-hoc `jq`.
* *Exemptions are reviewed, dated and shrink-only.*
  `.machine_readable/required-contexts-allow.txt` holds no unproducible
  context; its single entry is the `code_quality` data rule, removable only
  at the decision layer (enable Code Quality, or
  `scripts/remove-unsatisfiable-data-rules.sh`). Adding a line is a public
  promise that the requirement cannot be satisfied; the gate warns when an
  entry goes stale, so it cannot quietly become permanent.

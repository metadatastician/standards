[.lead]
The "echidna system" is the proof route of the Kautz-ladder ultraplan
(link:ULTRAPLAN-KAUTZ-LADDER-2026-10-19.adoc[], Wave 3 and the Wave 0/1
work it depends on): a Hypatia finding becomes a proof obligation,
echidnabot hands it to ECHIDNA, the result comes back as a receipt, and
Hypatia may then, and only then, report the finding at HYP-01 level
`sound`. This document maps what exists across the attached repositories,
names every seam that is not connected, compares three independent route
designs, recommends one, lists what has to be created, lays the proof
ladder over the prover policy, and plans the ultracode session that would
build it.

It does not change any code. Every claim about a repository cites a
repo-relative path. Facts about `echidna`, `verisimdb`, `panic-attack` and
`pons-asinorum` come only from what the attached repositories say about
them and are marked _second-hand_.

TIP: ECHIDNA itself is planned in the companion
link:ULTRAPLAN-ECHIDNA-ENGINEERING-ROUTE-2026-11-05.adoc[engineering-route
ultraplan] (2026-11-05). The two plans meet at `echidna.prove.result/1`.

== Verdict in one page

*Where it stands.* The two ends of the route are real and machine-checked;
everything between them is missing.

* Hypatia sends obligations: `Hypatia.EchidnabotObligation` builds a static
  GraphQL mutation with every value in variables, tested
  (`hypatia/lib/echidnabot_obligation.ex:3-109`).
* echidnabot stores each obligation as `PENDING` and nothing ever reads it
  again. The code says so (`echidnabot/src/api/graphql.rs:416`); the store
  trait has no update method (`echidnabot/src/store/mod.rs:91-96`); there is
  no query to read an obligation back.
* Hypatia's `Verdict.idr` gives `sound` exactly one constructor, `Rechecked`,
  which demands a confirming mechanical re-check
  (`hypatia/src/Hypatia/ABI/Verdict.idr:162-165`), proved and gated in CI.
  Its runtime mirror `Verdict.attach_recheck/3`
  (`hypatia/lib/hypatia/verdict.ex:99-117`) has no caller in `lib/`, so no
  runtime finding has ever reached `sound`.
* Even if a producer called `attach_recheck/3` today, it would bind a re-check
  to the finding's _file_ only, not its line or rule, and it checks the
  artefact digest's format without recomputing it
  (`hypatia/lib/hypatia/verdict.ex:99-117`). One re-check of a file would
  "confirm" every finding on that file.
* Quarantine-as-retraction is proved (`Retraction.idr`) and tested; nothing
  calls `Quarantine.retract_dependents/1`.
* echidnabot serves its whole GraphQL schema without authentication on
  `0.0.0.0` (`echidnabot/src/main.rs:327-341`, `src/config.rs:313-315`).
  Beyond submitting obligations, an unauthenticated caller can overwrite a
  repository's webhook secret through `updateRepoSettings`
  (`src/api/graphql.rs:522-540`), and so forge webhooks that start prover
  runs and post to GitHub, or write training rows through
  `recordTacticOutcome`. This is the most urgent item in the plan.
* The K2 element, `ProverRecommender`, trains every five minutes on rows it
  synthesises from aggregates, because the store it reads is not deployed
  (`hypatia/lib/neural/prover_recommender.ex:136-189`); nothing reads its
  output.

*What this session measured* (<<measured>>). Two facts change the design:

. A successful Lean proof prints nothing. Two different proofs have the
  same output digest, `sha256("")`. The digest Hypatia's existing re-check
  binds identifies a confirmed proof _hole_; it cannot identify a
  discharged _obligation_. Discharge needs its own typed evidence.
. Checking a Lean file executes code in it: `#eval IO.FS.writeFile` wrote a
  file during `lean`. An obligation drain that runs provers on submitted
  goals is remote code execution unless it is sandboxed, and the obligation
  endpoint has no authentication today (`echidnabot/src/api/graphql.rs:389-390`).

*What to build, in one sentence* (<<recommendation>>). Seal the route's
wire formats in one Idris2 package first, then run one pipe end to end on
the only class whose meaning HYP-01 already defines (a `sorry` hole in a
Lean file), with any stub shown orange; and keep one record family,
keyed by the ADR-008 content-id domains, as the store every later rung
reads from.

*Where it sits on the ladder.* Today the route is K0 with holes. Its first
honest claim is K0, scoped to proof-hole findings. It is the best first
candidate for K4 on the estate, because a kernel re-run on the same bytes
_is_ a rescan, so its training rows are true. It should not be the first to
claim K2, which the ladder defines as a conjunction the proof route cannot
satisfy alone. <<kautz>> scopes both.

*Wave 0 now, everything else after numbers.* Twelve small changes close
real holes, record what was measured and take the owner's rulings; they can
land now (<<wave0>>). The pipe, the drain and the learning
work stay behind the standing rule that nothing above Wave 1 is committed
before the experiments have numbers
(link:ULTRAPLAN-KAUTZ-LADDER-2026-10-19.adoc[] §Experiments).

== What the echidna system is

=== IS and IS NOT

*IS* the path from a finding to a mechanically checked verdict about it,
with the records that path leaves behind and the learning that reads them.

*IS NOT* a prover (ECHIDNA is the prover, _second-hand_), not a fixer (the
fleet is, behind exit 78), and not a review bot. It mutates no repository.

== Three routes, compared

Three architects worked from the same maps without seeing each other's
designs. Each was given one angle.

[cols="1,3,1,1,3",options="header"]
|===
|Route |Shape |Elegance / correctness |Dependability / security / privacy |Cost

|*A — proof-first (the elegant arm)*
|Seal every seam as one Idris2 package in standards (ProverId, Token, Goal,
Obligation, Lifecycle, Receipt, Binding, Severity), generate every
consumer's tables and fixtures from it, add a separately typed `Discharged`
support to HYP-01, then wire. Obligations only from total shape functions.
|9
|7
|About 10-14 engineer-weeks to the first runtime `sound`; needs Idris2 in
standards CI and an ECHIDNA receipt `/2` upstream.

|*B — pipe-first*
|One finding end to end in a container on the class HYP-01 already
defines (a Lean `sorry` hole): a new `Hypatia.ProofRoute`, an echidnabot
drain and read-back query, a stub ECHIDNA named as a stub that runs real
Lean, `attach_recheck/3` in the scan funnel, a report-back row that stays
orange while the stub is in the path. Harden after numbers.
|8
|8
|About 8 engineer-days to a demonstrable loop, then about 10 days of
hardening after the owner rules on the numbers.

|*C — data-first*
|One record family (`proof.attempt/1` events folded into `proof.status/1`)
keyed by ADR-008 domains, flat files in verisim-data first, an in-situ
re-check producer, a burrower ledger exporter, an echidnabot pull channel,
ProverRecommender v2 with goal-side features and a portfolio run, then
distillation with provenance and rung clauses.
|8
|8
|About 48 engineer-days end to end; K2 may come back refuted for lack of
portfolio-complete data, which the route records honestly.
|===

Aspects, beyond the two axes:

* *Security.* All three require the sandbox and authentication. B is the
  only one that runs prover code on the critical path early, so its
  hardening steps (auth, loopback bind, mandatory sandbox) cannot slip past
  the first non-local deployment.
* *Privacy.* C is the strongest: goal text and raw prover output stay in
  the private flat-file store and owned-hardware VeriSimDB; grid and
  report-back carry identifiers, tokens and digests only.
* *Drift.* A is the only route that closes vocabulary drift by
  construction. B and C close it by tests, which narrows but does not
  remove the `argued` row between the Idris2 model and the Elixir and Rust
  code.
* *Maintenance.* A turns standards from canon text into canon text plus an
  Idris2 package with CI. If that is unwanted, Hypatia can host the package,
  at the cost of echidnabot depending on Hypatia's ABI.
* *Learning.* Only C makes the K2 claim falsifiable: it drops the
  recommender's outcome-time features
  (`prover_recommender.ex:20-29,246-255`), splits held-out data by goal, and
  sets the bar at the larger of 0.66 and a per-class frequency baseline,
  because 0.66 is ECHIDNA's own ranker baseline (_second-hand_) and may
  measure a different task.

=== Recommendation (PROPOSED)

*The elegant arm is A.* The recommendation departs from it in order, not in
destination:

. Land the Wave 0 changes now (<<wave0>>): authentication first, then the
  other holes, the rulings, the measurements and the deeds. They are needed
  on any route.
. Run B's pipe as a *draft-only experiment*, on the one class HYP-01 already
  defines: a re-check of a Lean `sorry` hole, using the existing
  `Mechanical` support, bound to the finding's span and rule, inside the
  shared sandbox. Its job is to produce numbers and to find what the types
  must say, not to merge.
. Then write the specification and the Idris2 ABI (A's steps, starting with
  ProverId, Token, Receipt with Binding, Recheck and Severity), informed by
  what the pipe found, with the theory laws in Agda.
. Take the pipe out of draft against those types, writing only C's record
  family so every later rung reads one store.
. Add A's `Discharged` support for claim-proving obligations, the lifecycle
  and shape functions, and C's learning work only after E7 and the owner's
  rulings.

<<merged-prs>> lists this as 23 stacked PRs.

Why depart: the owner's rule puts numbers before any Wave 3 commitment, and
Idris2 cannot run in this environment while the estate's GitHub runners are
billing-blocked, so an ABI-first merge here would be a silent green. On the
dependable and secure axis, two live holes outrank new types: an
unauthenticated schema on `0.0.0.0` that can rewrite webhook secrets, and
prover code execution. And the hole re-check is the one class that reaches
runtime `sound` without new theory. The destination stays A's sealed ABI and
`Discharged` support, with C's record model. A demonstrable,
honestly-graded loop is about two weeks after Wave 0; the full A shape
arrives in roughly the quarter A needs anyway.

[[bypass]]
=== The proof route and exit 78

The proof route sends obligations straight from Hypatia to echidnabot. It
never passes the fleet's interlock. That is acceptable because the route is
a *sensor*, not an actuator: exit 78 and the Kautz-4 ruling govern
dispatch, apply, PR, issue and deploy actions on estate repositories
(`gitbot-fleet/docs/AUTOMATION-QUARANTINE.adoc`). It is acceptable only
while five conditions hold, each as code with a test:

. No forge write and no forge token anywhere on the obligation path.
. The prover always runs sandboxed (the code-execution probe shows why).
. The obligation endpoint requires authentication.
. Dispatch to echidnabot passes the rate limiter.
. Path, size and digest checks run before any prover does.

If any obligation path gains a write, the exemption ends and that path goes
through the work-order evaluator like every other mutation.

== The architecture in layers (PROPOSED)

=== Layer 1 — the proof-route ABI

One Idris2 package, `2-protocols/proof-route/` in standards (or in Hypatia,
<<decisions>> D-1), `%default total`, with accept and reject fixtures in the
style of `hypatia/scripts/check-verdicts.sh`:

[cols="1,4",options="header"]
|===
|Module |Content

|`ProverId`
|Closed slug vocabulary with a kernel class: small-kernel, SMT, model
checker, bounded checker. Replaces the four vocabularies. Unknown slugs are
refused, never relabelled.

|`Token`
|The five ledger tokens of `docs/README-EXPLAINME-STANDARD.adoc` with their
order and the weakest-step meet; the total map from attempt facts to a
token (SMT without a checked certificate caps at `argued`; model checkers
and Kani at `tested-only`; a dangerous axiom gives `open`); the monotone map
from token to HYP-01 level.

|`Goal`, `Obligation`
|A goal is formal text plus target path and target digest; an obligation
binds a goal to a finding. Identity by ADR-008 content ids. Obligations come
from shape functions; a goal proposed by a model is a different type and
can never reach `sound` without a shape witness that reproduces the same
goal id.

|`Lifecycle`
|`PENDING → RUNNING → CLOSED | REFUTED | INDETERMINATE`, terminal states
absorbing, requeue consuming fuel, a closing receipt whose goal id equals
the obligation's.

|`Receipt`, `Binding`
|`echidna.prove.result/2`: the `/1` fields plus prover version, goal digest,
proof-artefact digest, target digest and diagnostics. A receipt binds an
obligation only when all three digests match. Kernel stdout is diagnostic,
never binding. It must be a new schema tag, and both consumers need a
dual-accept release before ECHIDNA emits it: echidnabot rejects unknown
fields (`src/dispatcher/prove_result.rs:78-79`), so extending `/1` would
break it, while proof-burrower tolerates extra fields but refuses any tag
other than `/1` (`crates/burrower-core/src/echidna_contract.rs:124-152`).

|`Recheck`
|`ProverRecheck` v2 binds a re-check to the finding's span and rule, not
only its file, and its artefact digest is recomputed by the verifier, not
taken on trust.

|`Severity`, `Gen`
|The total map from token and lifecycle state to grid severity; generated
Rust and Elixir tables, Nickel contracts and JCS golden fixtures.
|===

=== Layer 2 — echidnabot, the drain

Store transitions and a `proofObligation(id)` query; a drain task beside the
scheduler loop that polls `PENDING` rows, checks path, size and digest, and
runs the prover in one of two ways only: delegated to ECHIDNA (the default,
`local_isolation = false`), or locally in the Podman/bwrap executor
(`local_isolation = true`, which refuses to start without a backend:
`echidnabot/src/config.rs:196-207`, `src/main.rs:1349-1358`). Whether
ECHIDNA sandboxes its own backends is _second-hand_ and becomes an explicit
trust-boundary row. One shared sandbox profile applies everywhere a prover
runs, including Hypatia's re-checker and any stub: read-only target, no
network, no secrets, dropped capabilities (`unshare -rn` isolates the
network only). Authentication on the whole schema, loopback bind by default,
a rate limit on `/graphql`. A report-back writer and SARIF output for the
grid. Creusot (Pearlite contracts) and Verus on the receipt parser and the
store transition function (PROOF-POLICY §1.2).

=== Layer 3 — Hypatia, the warrant

A `Hypatia.ProofRoute` client that keeps the `proofId`; an ingest that polls
results; an independent re-run of the kernel on the same bytes as the
witness (so the producer of the receipt never certifies it); `Verdict v2`:

* `Rechecked` keeps its meaning: a prover confirmed the hole the detector
  claimed.
* A new `Discharged` support and `Closed` constructor carry a bound receipt
  _and_ a confirming independent re-run, with a token of `proven` or
  `proven-with-postulates` (<<decisions>> D-3).
* Retraction by `(prover, version)`, so a kernel bug retracts only the
  verdicts resting on that version.

=== Layer 4 — records

`proof.attempt/1` (append-only events, JCS plus LF) and `proof.status/1`
(the fold; the content of the proof-status octad), keyed by ADR-008
content ids: `proof-goal`, `prove-result`, a new `proof-status` domain, and
a *versioned* obligation domain. The registered
`echidnabot-proof-obligation` domain hashes only `{claim, context, prover,
repo}` (`docs/decisions/ADR-008-profile-c-domains.json`), so an unchanged
claim on a new target revision, span, rule or finding would get the old id,
hit an absorbing terminal state and never run again. The route registers an
obligation v2 domain over the finding identity (rule, span), the goal id and
the target digest; v1 ids stay valid for legacy rows.

The records that live in a tracked tree carry identifiers, tokens, digests
and timestamps only. Goal text, claim and context, and raw prover output
are written to a private store outside any git-tracked path (owned
hardware, access-controlled), and the records point at them by content id.
Otherwise the route would recreate the `pending.jsonl` disclosure that
Wave 0 removes. The tracked flat files start under Hypatia's verisim-data
tree; a VeriSimDB projection follows once the stapeln bundle is deployed
(ruled 2026-10-19). Counts are always by goal id and result id, never by
row: E1 showed 21,498 rows collapsing to 136 keys.

=== Layer 5 — surfaces

* A grid row `echidnabot (proof status)` in the findings family, with a
  token-to-severity table and `gating: false` in the enrolment manifest. A
  stub anywhere in the path makes the row `not_run`, which the renderer
  already shows orange.
* A deed address: `(neurosym (ladder (rung :id K0 :scope proof-route
  :state measured :falsifier "…" :evidence "<path>" :measured "<date>")))`,
  a `deed_lint` side condition and one mapping-spec row. No ABNF change: clause
  names are open (`1-formats/deed/spec/abnf/deed.abnf:99-102`).
* A replacement for HYP-S003 (proof freshness) reading `proof.status/1`, as
  a K9 component or praxis deed under the DEED-K9 plan's P2.4.

=== Layer 6 — learning

ProverRecommender v2 reading `proof.attempt/1` with goal-side features only,
evaluated by an independent harness that holds the held-out split. If it
beats the bar, it is frozen into a class-to-prover order in
`lib/rules/proof_strategy_selection.ex` with a falsifier corpus and a
`@distilled_from` reference to an immutable manifest that lists, in order,
the result ids it learned from (the manifest's digest travels with the
reference). A digest alone could not say which rows were used once the
dataset grows. This is the first executed instance of "dumb rules from
smart learning" on this route.

[[ladder-proofs]]
== The proof and theory ladder

Each obligation sits on the prover PROOF-POLICY assigns
(link:../3-practice/PROOF-POLICY.adoc[]), in build order. A falsifier is the
planted case that must be refused.

Three fields are recorded for every row, in its home repository's
proof-status file, and none is written in another's place:

* the §5 token (`proven`, `proven-with-postulates`, `tested-only`, `argued`,
  `open`) for each leg;
* for a theory row, the §2.2 correspondence state of each recheck leg
  (`BRIDGE-PENDING` until the statement comparison is recorded and reviewed,
  then `RECONCILED`);
* for a theory row, the Proof Witness Grade of §8, derived from receipts and
  never asserted. The target is `PWG-2ii`, where the §2 recheck obligation is
  discharged, and `PWG-1` once every witness has a per-commit CI receipt.
  Below `PWG-3` a theorem is `ungraded`.

Agda entrypoints use the §2.1 invocation,
`agda --safe --without-K --cubical-compatible`. Rust rows name both default
verifiers, Creusot with Pearlite contracts and Verus (§1.2); a verifier not
yet run stays `open` with its reason, never omitted. Mathesis catalogues the
grades it derives from these receipts and assigns none (§8.5).

The ultraplan's ladder classifies capabilities, each with a falsifier
(link:ULTRAPLAN-KAUTZ-LADDER-2026-10-19.adoc[] §ladder). The proof route
climbs the same ladder, on a different rail from the fix fleet.

|A finding reported `sound` without a bound receipt and an independent

*Where the combined route departs from the ultraplan's path.*

. The first loop is a hole re-check, not ECHIDNA discharging obligations
  shaped from PA categories. That is K0 for proof-hole findings, not Wave 3
  discharge, and is labelled so.
. Until the stapeln VeriSimDB exists, the octad and panic-attack's `@covers`
  reconciliation are stood in for by flat files and Hypatia-internal
  reconciliation, labelled "not VeriSimDB".
. The ultraplan's K0 asks every reporter to emit SARIF; echidnabot emits none
  yet, so the grid row ships with SARIF, not only a report-back.
. The ultraplan proposes `(ladder :rung K2 :falsifier :measured)`; this plan
  needs the nested, scoped form `(ladder (rung :id … :scope …))` because a
  sub-claim such as the proof-route MRR must not read as the whole rung
  (<<decisions>> D-4).

*Where it differs from the fix-fleet climb.* The fleet reaches K2 only
through rescan-verified fix outcomes, which wait for the Wave 1 evaluator
and the end of exit 78. The proof route mutates nothing, so its K0 can
complete in parallel with Wave 1, and its labels are available for K2
earlier.

*Is a proof outcome its own rescan?* For an _in-situ_ attempt, yes: the
fact "kernel K at version v accepted term T for goal G on target bytes with
digest D, resting on axioms A" is reproduced by re-running K on the same
bytes. The scope is narrow, and the risks are named:

* A transcribed goal can be accepted while meaning something other than the
  claim. That correspondence row is `argued`, never `sound`.
* ECHIDNA's own trust level must never be the token; echidnabot caps at
  level 2 and hard-codes solver integrity.
* An SMT result without a checked certificate is `argued`.
* A proof resting on `believe_me` or `sorry` is `open`.
* The only live obligation producer today is a prose claim; data may be too
  scarce for K2, and the deed then records `:state refuted`.

== Assumptions and limits

* The six subsystem maps and the three route designs were produced by
  agents. An independent critic then tried to refute the ten most
  load-bearing claims: six held, four were refuted and are corrected above
  (the meaning of `Mechanical/confirms` for hole findings; how each
  consumer treats unknown receipt fields; what `local_isolation = false`
  means; which repositories have a chora deed). The critic's security
  finding (the whole GraphQL schema is unauthenticated) and every other
  code claim this plan relies on were re-opened by hand and hold. The two
  Lean probes were reproduced independently.
* The three designs disagree on names: the record family, the lifecycle
  states, the ABI's home and the rung clause. This plan picks one of each
  and lists the open ones in <<decisions>>.
* Effort figures are the architects' estimates, not measurements.
* No Idris2, Agda, Rocq, Creusot or Kani check was run for v0.2.2 or
  earlier. For v0.2.3, Agda 2.8.0.2, Lean 4.35.0 and Coq 8.18.0 checked
  echidnabot's receipt-boundary theory (hyperpolymath/echidnabot#195); the
  Idris2 results cited are Hypatia's own CI run. No Creusot, Verus or Kani
  check has been run.
* Nothing in this document is a ruling. The rulings it respects are the four
  Kautz rulings of 2026-10-19, the DEED-K9 rulings of 2026-10-20,
  PROOF-POLICY of 2026-10-26, and its amendments of 2026-11-04 (§8, Proof
  Witness Grades) and 2026-11-07 (§1.2, Creusot/Pearlite and Verus).
